# unreal

The Unreal port: the C++ payment core and the Unreal plugin around it. It is in development. The glue (phase 2 of the port) runs on Linux with UE 5.8.4; there is no release, no project settings page (`UScfgSettings`), no developer guide and no CI job for the editor yet (phases 4 and 5), and the other engine versions and platforms are unverified (see [What is verified](#what-is-verified)). What exists:

- `ScfgCore`, the engine-independent core in plain C++20, with its CMake build and tests and the drivers of the shared integration and server suites (see [Development](#development)). The Python core (`plugin/game/python-packages/scfg_core/`) is the reference, and the C# port (`unity/`) is the closest template. The core replays every conformance vector in `conformance/vectors/`.
- The `Scfg` plugin (`Plugins/Scfg/`), which builds the core as its `ScfgCore` module under Unreal Build Tool (see [Under UBT](#under-ubt)) and adds the glue, the `Scfg` module: a game-instance subsystem with a Blueprint API over a facade, the worker, the store, the HTTP transport, the localhost checkout page server, and the Slate payment sheet and restore screen (see [The glue module](#the-glue-module)). Two test-only modules run the conformance vectors and the glue's tests inside the editor.
- The development project `Project/ScfgDev/`, with a showcase that is played end to end in a rendered window on Linux (see [The Linux e2e](#the-linux-e2e)).

Apart from the core module's one registration file, nothing in the core includes an Unreal header.

## Commands

Everything in one place; each section below says what the command does and checks. Unreal commands run headless, under a timeout, and kill what they started by process group.

```bash
# the core, from unreal/ (CMake 3.25+, Ninja, a C++20 compiler; see Development)
cmake --preset release && cmake --build --preset release && ctest --preset release            # also asan, clang-libcxx
# the C++ halves of the shared suites, from the repository root
uv run pytest -m integration tests/integration/test_cpp_core.py   # the integration twins (anvil, solana-test-validator)
uv run pytest tests/server_security -m cpp_server                  # the localhost checkout server suite's cpp half
# the plugin under UBT (UE 5.8; see Under UBT)
uv run python tools/run_unreal_build.py [--target ScfgDevEditor|ScfgDev] [--config Development|Shipping|...] [--platform Linux]
    [--engine DIR] [--project UPROJECT] [--timeout S] [--log FILE] [-- <UBT arguments>]
uv run python tools/run_unreal_tests.py [--filter Scfg.Core] [--expect N] [--no-build] [--engine DIR] [--project UPROJECT]
    [--target ScfgDevEditor] [--timeout S] [--build-timeout S] [--report-dir DIR] [--log FILE]
# the showcase end to end, on an X server of its own (it re-runs itself under xvfb-run -a; see The Linux e2e)
uv run python tools/run_unreal_e2e.py [--family evm|arc|solana] [--packaged] [--no-build] [--screenshots DIR] [--keep]
    [--engine DIR]
uv run pytest -m unreal_e2e                                        # one test per family; SCFG_UNREAL_PACKAGED=1: packaged
# the copies and tables the plugin keeps in step with the shared sources
uv run python tools/sync_web_page.py --check                       # Plugins/Scfg/Resources/Web/
uv run python tools/check_text_ids.py --engine unreal              # the sheet's text ids
```

`run_unreal_build.py` and `run_unreal_tests.py` exit 0 only when everything passed; `run_unreal_e2e.py` exits 0 when the run passed, 1 when it failed, and 2 when it refused to start a game or a prerequisite is missing. `--engine` defaults to `$UE_ROOT`, else `/mnt/files/UnrealEngine`.

## Development

Needs CMake 3.25 or newer, Ninja and a C++20 compiler (g++ 13, or Clang with libc++ for the `clang-libcxx` preset).

```bash
cd unreal
cmake --preset release && cmake --build --preset release && ctest --preset release   # -O2, assertions kept
cmake --preset asan && cmake --build --preset asan && ctest --preset asan            # AddressSanitizer + UBSan, -funsigned-char
cmake --preset clang-libcxx && cmake --build --preset clang-libcxx && ctest --preset clang-libcxx   # clang++ -stdlib=libc++

# one group or one test while iterating (ctest runs one test per group)
build/release/scfg_core_tests --list
build/release/scfg_core_tests --group EngineTests
build/release/scfg_core_tests --test Tier1.amounts
build/release/scfg_core_tests --test Tier2.smoke/evm_unlock_paid

# the driver against local chains (anvil / solana-test-validator on PATH), from the repository root
uv run pytest -m integration tests/integration/test_cpp_core.py
# the localhost checkout server against the shared security suite (the cpp_server half), from the repository root
uv run pytest tests/server_security -m cpp_server
```

Every preset builds with `-Werror`, and no ctest group may fail or skip; ctest also runs `SharedLibraryExports`. A new test group must be added to `SCFG_TEST_GROUPS` in `CMakeLists.txt`, or `RunnerTests.EveryGroupIsRegistered` fails. `RunnerTests.NothingLeftOut` checks that no vector, topic or test is filtered out.

Environment:

- `SCFG_VECTORS` overrides the vectors directory the tests read (default: `conformance/vectors/`), in the CMake binary and in the editor's `Scfg.Core.*` tests (whose default is the `conformance/vectors` found by walking up from the plugin's folder).
- `SCFG_REQUIRE_LOCALES=1` (set in CI) makes `LocaleTests` fail when `tr_TR.UTF-8` or `de_DE.UTF-8` is not installed. Without it, the reruns fall back to another installed locale with a decimal comma. When there is none either (a stock Ubuntu, Docker or WSL image has only `C`, `POSIX` and `en_US`), `LocaleTests` fails. Install the two locales with `sudo locale-gen tr_TR.UTF-8 de_DE.UTF-8` (Debian: enable them in `/etc/locale.gen` first).
- `SCFG_REQUIRE_CPP=1` (set in CI) makes the `test_cpp_core.py` twins and the `cpp_server` half of `tests/server_security` fail, rather than skip, when the toolchain is missing or unusable. `tests/integration/cpp_driver.py` builds each driver (`scfg_core_driver`, `scfg_server_driver`) once per session into `unreal/build/integration`. It takes cmake from `PATH` or `~/.local/bin` and needs 3.25 or newer. The compiler is `$CXX` when its program resolves, else `c++`, `g++` or `clang++`. It builds with Ninja, or with make when there is no Ninja. Without one of these the twins skip. A configure or compile failure of the code itself always fails. The EVM and Arc twins also need `anvil`, which CI installs. The `cpp_server` half of `tests/server_security` is deselected unless the `-m` expression names `cpp_server` (its `conftest.py` registers the marker and deselects it, so a plain `uv run pytest` never builds the driver); CI's `cpp-core` job runs it.

## Under UBT

The plugin is `Plugins/Scfg/`: `Scfg.uplugin` (version 0.3.0, `EngineVersion` 5.8.0, no content) with five modules, each `LoadingPhase` `Default`: `ScfgCore` and the glue `Scfg` (`Runtime`) on Win64, Mac, Linux, Android and iOS (the last two best effort, never built: see [Mobile](#mobile)), the editor module `ScfgEditor` (`Editor`) on Win64, Mac and Linux, and the test-only `ScfgCoreTests` and `ScfgTests` on Win64, Mac and Linux (`UncookedOnly`: built into the editor and uncooked targets, never into a cooked game; ModuleDescriptor.cs:792, where `DeveloperTool` would follow `bBuildDeveloperTools`, true for Development games). Only UE 5.8 (5.8.4 on Linux) has been built against; 5.6 and 5.7 are unverified.

Building, from the repository root (headless; `--engine` defaults to `$UE_ROOT`, else `/mnt/files/UnrealEngine`):

```bash
uv run python tools/run_unreal_build.py --target ScfgDevEditor --config Development      # the editor (modular)
uv run python tools/run_unreal_build.py --target ScfgDevEditor --config Development -- -DisableUnity   # no unity files
uv run python tools/run_unreal_build.py --target ScfgDev --config Shipping               # a packaged game (monolithic)
```

The wrapper runs `Engine/Build/BatchFiles/Linux/Build.sh <target> Linux <config> -Project=<uproject> -WaitMutex -NoHotReload -UBAHost=127.0.0.1` (UBT's build accelerator otherwise listens on 0.0.0.0:1345) under a timeout (default an hour; on expiry, or when the wrapper gets SIGTERM, SIGINT or SIGHUP (its handlers are in before UBT starts), it kills UBT's whole process group, even when only a descendant of `Build.sh` is left) and fails when UBT fails or prints any `warning:` or `error:` line other than one located in an engine file and reached through engine files only: a warning in an engine header that our code triggers fails the build, and so does any UBT message, which names no file. A game target (any not named `*Editor`) also fails unless its link inputs (`Intermediate/Build/Linux/x64/<target>/<config>/<binary>.rsp`; a monolithic receipt lists no modules) hold a `ScfgCore` object and none of `ScfgCoreTests` or `ScfgTests`, so a test module can never ship unnoticed. Both targets set `bWarningsAsErrors = true`. The engine is an installed build, so they share its build environment, and UBT refuses a changed setting there unless `bOverrideBuildEnvironment = true`, which they also set: the override only reaches the modules UBT compiles here, which are ours. Products land in `Project/ScfgDev/Binaries/Linux/` (`libUnrealEditor-ScfgCore.so`, `libUnrealEditor-ScfgDev.so`, `ScfgDev-Linux-Shipping`) and intermediates in `Project/ScfgDev/Intermediate/` (the plugin's under `Intermediate/External/`), all gitignored; the plugin folder gets only UHT's generated code, in `Plugins/Scfg/Intermediate/Build/Linux/<UnrealEditor or UnrealGame>/Inc/<module>/UHT/` (UBT writes a plugin's generated code into the plugin's own folder so the plugin can move between projects, `UEBuildTarget.cs:6879-6904`), which the plugin's `.gitignore` covers. The project's `Config/` is committed (`DefaultEngine.ini`: the Home panel off and the showcase's game instance and map; `DefaultGame.ini`: no zen store for a cook; `DefaultInput.ini` as the 5.8 editor writes it, and `DefaultEditorSettings.ini`, which turns off the editor's usage analytics and the unattended crash report upload, both on in `BaseEditorSettings.ini`; `ScfgDev.NoTelemetry` checks them), so a local ini cannot change a build or a test run unnoticed; the project disables the `AndroidFileServer` plugin, whose editor module otherwise writes a random `SecurityToken` into `DefaultEngine.ini` on the first run.

`ScfgDev.Smoke` is a smoke test in the development project's module: it calls `scfg::amounts::parse_amount` from another module, which proves the core links and runs inside the editor process. Run by hand, the editor needs the three switches `run_unreal_tests.py` passes (see below): `-notraceserver`, `-NoZenAutoLaunch` and `-ddc=InstalledNoZenLocalFallback` (`NoZenLocalFallback` on a source engine), or it starts a trace server and a zen DDC service that listen on every interface.

```bash
"$UE_ROOT/Engine/Binaries/Linux/UnrealEditor-Cmd" "$PWD/unreal/Project/ScfgDev/ScfgDev.uproject" -ExecCmds="Automation RunTests ScfgDev.Smoke;Quit" \
  -unattended -nullrhi -nosplash -stdout -notraceserver -NoZenAutoLaunch -ddc=InstalledNoZenLocalFallback -ReportExportPath=<dir>
# or: uv run python tools/run_unreal_tests.py --filter ScfgDev.Smoke
```

The conformance vectors run inside the editor process too, through `ScfgCoreTests`, by the same runner code as the CMake binary (one copy: `core-tests/tier1/` is a source directory of the module through `ConditionalAddModuleDirectory`, so a new topic file needs no edit; the five runner files of `core-tests/support/` that it needs, `Tier1`, `Tier2`, `JsonEq`, `ConfigJson` and `Vectors`, come in through one-line shims in `Private/CoreTests/`, because UBT can only add whole directories and that one also holds the CMake-only `Test.cpp`, `Lint.cpp` and `Locales.cpp`). `Private/ScfgCoreAutomationTests.cpp` turns them into automation tests (`IMPLEMENT_COMPLEX_AUTOMATION_TEST`, `EditorContext | EngineFilter`), enumerated from the vector files at run time:

| Test | What |
|---|---|
| `Scfg.Core.Tier1.<topic>` | one per `conformance/vectors/tier1/*.json` (18) |
| `Scfg.Core.Tier2.<group>.<name>` | one per `tier2/<group>/<name>.json` (121; the id's `/` is a `.` in the name), immediate transport |
| `Scfg.Core.Tier2Deferred.<group>.<name>` | the same vectors, requests answered one per pump turn |
| `Scfg.Core.NothingLeftOut` | the vector files, listed again through the engine's file manager, and the tests each complex test generates are the same names (no count is pinned, as in the CMake `RunnerTests.NothingLeftOut`), and the registered Tier 1 topics are the topic files |

```bash
uv run python tools/run_unreal_tests.py --filter Scfg.Core   # builds ScfgDevEditor first, then runs the editor headless
uv run python tools/run_unreal_tests.py --filter Scfg        # everything: Scfg.Core, Scfg.Glue and the dev project's ScfgDev.*
# --expect N: fail unless at least N tests passed (a minimum; today 261 for Scfg.Core, 413 for Scfg)
```

`tools/run_unreal_tests.py` builds the editor target through `run_unreal_build.py`, then runs `UnrealEditor-Cmd <uproject> -ExecCmds="Automation RunTests <filter>;Quit" -unattended -nullrhi -nosplash -stdout -notraceserver -NoZenAutoLaunch -ddc=InstalledNoZenLocalFallback -ReportExportPath=<dir>` (`NoZenLocalFallback` on a source engine) under a timeout (default 1800 s; on expiry, SIGTERM, SIGINT or SIGHUP it kills the editor's process group), reads `<dir>/index.json` (UTF-8 with a BOM) and prints `<n> passed, <m> failed`; it fails unless the editor exited 0, m is 0, no test was left unrun or in process, every entry of the report's `tests` list succeeded and their number is n, n > 0 and n reaches `--expect`. It prints which vectors the tests read (from `NothingLeftOut`'s log entry) and whether `$SCFG_VECTORS` chose them. Locale reruns stay CMake-only: inside the editor `setlocale(LC_ALL, nullptr)` is `"C"` (`NothingLeftOut` logs it).

What a test run opens on the network, measured with `ss -tunap` (listeners, outbound connections and DNS sockets of the editor's session) sampled during a run: only the editor's trace control port, `0.0.0.0:1985`, an accepted exposure, and the tests' own loopback sockets. TraceLog compiles that listener in under `TRACE_PRIVATE_ALLOW_TCP_CONTROL` (`TraceLog/Private/Trace/Control.cpp:18`, `Trace/Config.h:82-84`), starts it unconditionally (`Writer.cpp:1050`) and binds it to every interface (`Detail/Unix/UnixTrace.cpp:171-175`); no command-line switch turns it off (`-trace=`, `-tracehost=`, `-notrace*` do not touch it), so only a source-engine build could. Everything else is kept off:

- `-notraceserver` (`TraceAuxiliary.cpp:2365`): no UnrealTraceServer daemon is forked (it would outlive the run with ports 1981/1989).
- `-NoZenAutoLaunch` (`ZenServerInterface.cpp:1753`) and a DDC graph without `ZenLocal` (the file cache instead): the editor neither launches nor restarts the per-user zen DDC service. Auto-launch would listen on every interface (`*:8558`: `BaseEngine.ini` sets `[Zen.AutoLaunch] RemoteNetworkService=GeneratedStaticKey`, and only `None` adds `--http-forceloopback`, `ZenServerInterface.cpp:2085-2089`). Setting `None` in our `DefaultEngine.ini` instead is not safe: the service is shared per user on port 8558, and auto-launch shuts down a running instance whose command line differs from the one it wants (`:4153-4190`, `:4221-4237`), which could be another editor's. With `-NoZenAutoLaunch` the auto-launch path, its install update and its shutdowns are skipped entirely (`:2852`). The tests need no DDC.
- The project disables the `UdpMessaging` plugin, whose transport otherwise binds `0.0.0.0` and joins the multicast group 230.0.0.1:6666 on every interface; the in-process automation controller does not need it.
- The `ValidatePlatforms` UBT run the editor starts inherits the 1985 socket for its few seconds; UBT builds pass `-UBAHost=127.0.0.1`.
- The checkout page tests (`Scfg.Glue.LocalServer.*`, the facade's browser flow) listen on `127.0.0.1:<random port>` only: `ListensOnLoopbackOnly` reads the bind address from `/proc/net/tcp`, and `ss -tlnp` sampled every 50 ms during a whole `--filter Scfg` run listed only `127.0.0.1:<port>` listeners of the editor besides `0.0.0.0:1985`.
- Two Unix limits of the checkout page's `FSocket`s, kept (ruling R2-14) because the public `FSocket` API cannot avoid them; neither exposes data. (1) Accepted connections are inheritable: `CreateSocket` sets `SOCK_CLOEXEC`, but `FSocketBSD::Accept` is a plain `accept()` (`SocketsBSD.cpp:130-143`), and `FPlatformProcess::LaunchURL` forks and `execl`s `xdg-open` without closing descriptors (`UnixPlatformProcess.cpp:696-714`). A page connection open at the moment "Open in browser" is pressed again is inherited by `xdg-open` and a browser it starts, and stays half-open (no FIN) until that process exits; the answer itself is unaffected, and the listener is close-on-exec. (2) `FSocket::Send` passes no `MSG_NOSIGNAL` (`SocketsBSD.h:147`), and the engine ignores `SIGPIPE` only once its crash handler is installed, which it skips under a debugger (`UnixCommonStartup.cpp:305-321`): debugging the game under gdb or lldb, a browser that resets a connection mid-answer stops the process with `SIGPIPE` (continue past it; the plugin does not change the process's signal disposition). Our own POSIX sockets (`accept4(SOCK_CLOEXEC)`, `MSG_NOSIGNAL`, as `core-driver/ServerMain.cpp`) would remove both.
- `Scfg.Glue.Http.*` serve their JSON-RPC node on `127.0.0.1:<random port>` (`HTTPServer` binds the loopback address for `localhost`, `HttpListener.cpp:68-70`), and post only to it and to `127.0.0.1:1` (refused).
- Nothing goes to Epic: the project's `DefaultEditorSettings.ini` turns off the editor's usage analytics (`AnalyticsET` to `datarouter.ol.epicgames.com`, on by default) and the crash report upload of an unattended run that crashes (CrashReportClient, also on by default). The per-user `~/.config/Epic/UnrealEngine/5.8/Saved/Config/LinuxEditor/EditorSettings.ini`, shared by every 5.8 project, would override them; it holds neither key here, and `ScfgDev.NoTelemetry` would catch one.
- Nothing goes to Google: the editor's Home panel checks the internet connection with a GET of `https://www.google.com/generate_204` every 5 s (`SHomeScreen::CheckInternetConnection`, `MainFrame/Private/HomeScreen/SHomeScreen.cpp:939-967`, through the HTTP retry system, so no `LogHttp` line names it). The project's `DefaultEngine.ini` sets `[ConsoleVariables] HomeScreen.EnableHomeScreen=0` (a read-only cvar, `MainFrameModule.cpp:54-59`; the Home tab is then not registered, which a hand-opened editor shows too), and `ScfgDev.NoTelemetry` checks it and that no analytics provider started.

UBT caches each target's build plan (`Project/ScfgDev/Intermediate/Build/Linux/x64/<target>/<config>/Makefile.bin`) and, in 5.8, reuses it even under `-NoUBTMakefiles`, after a `.uplugin` gained a module, and when `-DisableUnity` is added or dropped: the build then silently leaves the new module out, or stays unity. `run_unreal_build.py` therefore deletes that one file before every build (a few seconds of planning).

How the core fits UBT:

- **Engine dependency.** `ScfgCore` depends on `Core`, privately, for one reason: a module needs `IMPLEMENT_MODULE(FDefaultModuleImpl, ScfgCore)`, which needs `Modules/ModuleManager.h`. That one line lives in `Private/ScfgCoreModule.cpp`, which the CMake build leaves out (`list(FILTER ...)` in `CMakeLists.txt`) and the lints exempt from `OnlyStdIncludes` only (`ModuleFileIsMinimal`). The public headers include no Unreal header, so no dependent gets `Core` through `ScfgCore`. The dependency also gives the module `Core`'s shared PCH.
- **Flags.** `PCHUsage = UseExplicitOrSharedPCHs`, no `CppStandard` override (UBT passes `-std=c++20`), `bUseRTTI` and `bEnableExceptions` left at false. Every file is compiled with `-fno-rtti`. Exceptions are on in editor builds anyway: UBT turns them on for every target compiled against the editor (`-fexceptions`), and off in game builds (`-fno-exceptions`). The core is written for either: it never throws or catches. C++20 coroutines need no flag.
- **Force-includes.** Each core file is compiled with the shared PCH of `Core` and a generated `Definitions.ScfgCore.h` force-included, so Unreal's macros (`check`, `TEXT` and the rest) are defined in every core translation unit: that is what `scfg_core_poisoned` guards against. Built with `-NoPCH -NoSharedPCH` only the definitions are force-included, and the core still builds.
- **Exports (`SCFGCORE_API`).** UBT defines `SCFGCORE_API` as `DLLEXPORT` inside the module, `DLLIMPORT` in a module that uses it (the editor build), and empty in a monolithic build. `Public/Scfg/Export.h` defines it empty outside UBT, and under UBT defines `DLLEXPORT`/`DLLIMPORT` as Unreal's platform headers do when no PCH has (the `-NoSharedPCH` build). It goes on every class with a member a `.cpp` defines (`class SCFGCORE_API Json`), every non-inline free function, every friend function such as `BigInt`'s operators (a class's export does not cover its friends) and the extern `VERSION`, never on a template, an inline function or a `constexpr` variable. Header-only classes (aggregates, interfaces with only inline or pure members) have nothing to export and carry none. Linux editor builds compile with `-fvisibility-ms-compat -fvisibility-inlines-hidden`, so a function without the macro is hidden and a call from another module fails to link. `LintTests.ExportsMarked` checks it.
- **Unity builds.** UBT's unity file `Module.ScfgCore.cpp` includes every core `.cpp` in one translation unit (`scfg_core_unity` is its CMake twin). Both targets set `bUseAdaptiveUnityBuild = false`: UBT's adaptive unity takes the files it believes are being edited out of the unity file, and it looks for `.git` only in the engine's folder, the project's and the project's parent, so here (an installed engine, the repository three levels up) it falls back to Perforce's rule and takes out every writable file, which is every file. `-DisableUnity` compiles each file alone.

## The Linux e2e

```sh
uv run python tools/run_unreal_e2e.py --family evm|arc|solana [--packaged] [--no-build] [--screenshots DIR] [--keep]
uv run pytest -m unreal_e2e                            # the same, one test per family (deselected by default)
```

## Mobile

Best effort (spec, Targets): **Android and iOS packaging and device runs are BLOCKED**, because no Android SDK/NDK and no Xcode are installed here. What follows is built and tested on Linux, and reasoned from the engine's source for the phones; none of it has run on one.

On a phone (`FScfgEnginePlatform::IsMobile()`: `PLATFORM_ANDROID || PLATFORM_IOS`) the facade makes every checkout controller with `mobile` set, so the methods are picked exactly as Python's and Godot's are: no browser method, only the QR code and the manual transfer (`methods()` is `qr, manual`). The QR step has an "Open wallet app" button (unless `methods.qr.wallet_button` is off, the Ren'Py and Godot sheets' rule) that hands the payment request (EIP-681 `ethereum:<token>@<chain id>/transfer?...`, or Solana Pay `solana:<recipient>?amount=...&spl-token=...&reference=...`) to `FPlatformProcess::LaunchURL`. Android sends it as an `ACTION_VIEW` intent with `CATEGORY_BROWSABLE` to the app registered for the scheme (`GameActivity.java.template`, `AndroidThunkJava_LaunchURL`; with no wallet installed the engine logs "Could not find an application" and nothing opens); iOS keeps the scheme (`FParse::SchemeNameFromURI` reads `ethereum:` and `solana:` as schemes) and calls `UIApplication openURL`, which needs no `LSApplicationQueriesSchemes` entry (only `canOpenURL` does). Back in the game, nothing calls back: the worker's polling (every 3 s while the sheet is open) finds the transfer, as for a QR payment. The manual step works as on the desktop (Copy, the hash field, Paste). Keep the QR code or the manual transfer enabled for a phone: with only the browser method on (`Methods.Qr.bEnabled` and `Methods.Manual.bEnabled` false, or `Methods.Qr.Chains` leaving out the chain and manual off) the configuration is valid (`methods.none_enabled` counts the browser) but a phone has no method, and its method step offers nothing but Cancel; the same holds in Python and Godot. A link `LaunchURL` refuses (a game's `FCoreDelegates::ShouldLaunchUrl`, such as a parental gate) is logged as one warning, `scfg: cannot open the ethereum: link: <why>` (the scheme only, never the link).

Why there is no localhost path on a phone (research §15):

- Android blocks cleartext HTTP by default from Android 9 (API 28); only Android 17 (API 37) adds an implicit exemption for `localhost` and loopback IPs. A browser opening `http://127.0.0.1:<port>/` would be refused without a Network Security Config the game would have to ship.
- iOS 17 App Transport Security no longer allows connections to IP addresses by default (`NSAllowsLocalNetworking` or an exception would be needed).
- While the browser (or the wallet) is in front, the game is in the background and very likely suspended, so its page server could not answer anyway.

The RPC calls need no change: the core's built-in RPC urls are all `https://`, which neither rule affects. An `http://` url in `RpcUrls` may be refused on a phone (Android cleartext, iOS ATS); use `https://`.

How the code stays buildable there (reasoned from the engine's Build.cs conventions and sources, not compiled): the core is standard C++20 (the libc++ of NDK r27c and Xcode; no `from_chars` of a double, which NDK r27c lacks); the glue's module list is the same on every platform, since `ApplicationCore`, `HTTP`, `ImageWrapper`, `InputCore`, `Projects`, `Slate`, `SlateCore`, `UMG` and `Sockets` are engine runtime modules with Android and iOS implementations (`Sockets/Private/Android`, `Sockets/Private/IOS`), and the localhost server's code compiles there but is never started; only the page's files are not staged (`Scfg.Build.cs`, `UnrealPlatformGroup.Desktop`). The store takes its `IPlatformFile` path there (its own POSIX calls are for Linux and Mac only), so `Saved/Scfg/state.json` goes through the engine's own path mapping (on Android, the app's storage). The test modules stay desktop-only.

The mobile override: a desktop game started with `-scfg-mobile` (not in Shipping, where the switch is compiled out) runs the phone's checkout, wallet button included, with the engine's `LaunchURL`; the tests use `FScfgEnginePlatform(true)` or the fake platform's `bMobile` (`Scfg.Glue.Mobile.*`, whose header maps the Python and Godot mobile tests to their twins).

## The glue module

`Plugins/Scfg/Source/Scfg/` is the Unreal side of the plugin (`Runtime`; depends on `Core`, `CoreUObject`, `DeveloperSettings`, `Engine`, `SlateCore` and `UMG` publicly, for the subsystem, the project settings, the Blueprint types, the default sheet host and its UMG wrapper in `Public/`, and on `ApplicationCore` (the clipboard), `HTTP`, `ImageWrapper` (the logo), `InputCore`, `Projects`, `ScfgCore`, `Slate` and `Sockets` privately, so the core's headers stay out of a dependent's include path). Everything in it runs on the game thread: no threads, tasks or blocking waits, and it never hands a `scfg::Co` or `scfg::Future` to its callers. Its classes are in `Private/`; the ones the tests use carry `SCFG_API`, and `ScfgTests` adds `Scfg/Private` to its include path.

### How it fits together

```
the game (C++ or Blueprint)
 └─ UScfgSubsystem, one per game instance; the Blueprint nodes (UScfgPayAsyncAction, UScfgBlueprintLibrary) call it
     └─ FScfgFacade: the configuration, the flows, the queries, and its pump (every core-ticker frame)
         ├─ FScfgStore: Saved/Scfg/state.json, loaded before the worker, saved after each OnStateChanged
         ├─ FScfgWorker: the core's Engine and its commands, one at a time from the core ticker
         │   └─ FScfgHttpTransport: JSON-RPC over FHttpModule to the chains' RPC urls
         ├─ FScfgCheckout / FScfgRestore: the core's CheckoutController / RestoreController, one per screen,
         │   │                            sending commands to the worker through FScfgSubmitter
         │   └─ FScfgLocalServer: the checkout page on 127.0.0.1, from the browser method until the sheet closes
         │                        (after keep playing: until the payment is final or methods.browser.timeout_min)
         └─ IScfgSheetHost: FScfgDefaultSheetHost (the default), a game's own host, or a UMG host with UScfgSheetWidget
             └─ SScfgPaymentSheet / SScfgRestoreScreen (SScfgScreen), SScfgToast
```

- **A payment.** `Pay` makes a `CheckoutController` (given the page server's factory) and asks the host to open a screen for it. The screen shows the controller's state and calls its buttons; the controller sends its commands (start the session, report a hash, set the UI status, discard the session, build a Solana payment for the page) through the Submitter to the worker, which runs them on the Engine and polls the chain. The facade's pump hands the worker's outcomes to the controllers and polls them, which also pumps the page server's sockets. The results go to the call's callback (`Pay`: this call's result and every later one of that payment, also after the player kept playing; `PayAsync` and the Pay node: once, when the sheet closes), else to `OnPaymentResolved` (`ScfgSubsystem.h` has the exact rules). `Restore` is the same with a `RestoreController`.
- **Game thread only.** Nothing in the glue starts a thread, a task or a blocking wait. The worker, the facade's pump, the store's retries and the default host's checks are core-ticker (`FTSTicker`) elements; HTTP answers complete on the game thread (`CompleteOnGameThread`); the page server's sockets are non-blocking and read from the pump; the screens run in Slate's tick. A public call from another thread is refused by one guard (`Private/ScfgGuard.h`): a `scfg: <Function>() must be called on the game thread` line every time, an `ensure` (once per process), and a Failed result delivered on the game thread at the next core-ticker frame (a query: its neutral value). The subsystem checks first, so the facade's own check of the same guard is reached only by the tests; the worker, the store and the transport are reached only from the facade and keep `check(IsInGameThread())` as an assertion. No `scfg::Co` or `scfg::Future` crosses the glue's API: the worker drives the core's coroutines through `scfg::Job` and hands back `Result<T>`.
- **Teardown order** (`Deinitialize`, or `BeginDestroy` when the game instance was collected without it; ruling R2-11), exactly: the open screens and their controllers are closed (a controller's destructor stops its page server); the worker is stopped and destroyed, which destroys its Jobs, then the Engine, then the transport (its requests unbound, then cancelled); the store flushes what it owes and is destroyed; the pump leaves the ticker. Nothing is delivered to the game during the teardown (no callback, event or notification: the C++ `PayAsync` and `RestoreAsync` callbacks are dropped there as the Blueprint nodes' pins are), and nothing in it creates a UObject or runs a game widget's focus handler inside garbage collection.
- **Error ownership** (ruling R2-8). Each `Err` that reaches the glue is logged by its owner, on `LogScfg` at `Error`, as `scfg: <heading> <Err::str()>`; the callers turn it into a Failed result with its code and never log it again. The headings:

  | Heading | Logged by | How often |
  |---|---|---|
  | `worker error:` | the worker (the facade's `OnError`): every Err of a command but a `CancelledError`, before the command's callback runs, callback or not | once per Err |
  | `cannot read the stored receipts:` | the store, while it loads `state.json`: a file it cannot read, or a corrupt one it cannot move aside (the store is then blocked: no payments), and a save of the cleaned stores that fails then (a corrupt file moved aside and a dropped record are warnings) | once per load |
  | `cannot save the payment state:` | the store, saving (a `dumps` Err included) | once until a save succeeds; retried every 10 s |
  | `cannot start the checkout page:` | the page server: its factory (page files missing, the logo) or its start (cannot listen) | each time the player opens the browser method; the method then shows `browser_unavailable` |
  | `cannot start the payment engine:` | the facade: `FScfgWorker::Create`'s Err (stored records the Engine refuses), which nobody else reports | once per start |
  | `cannot read the stored receipts:` | the facade: a query (`Owns`, `HasTipped`, `TipTotal`, and `Pay`'s already-owned check) answered from the stored receipts while no worker snapshot is live (before the start, during a wipe), when `compute_ownership` fails on them | on every such call, not once |
  | `cannot build the payment link:` | the facade: the wallet-app button or a screen reading the link (the QR step reads it on every rebuild), when the controller's `payment_uri` fails | once per controller, whoever asks first |
  | `screen:` | the facade (`ReportScreenError`): an `Err` a screen's action got back from the controller, unreachable with the Engine's own results: `explorer_url` (read on each rebuild of the done step), `next_step`, `set_tip_amount`, `apply_custom_amount`, `choose_network`, `submit_hash` and the restore screen's `check_tx` (each press) | each failing read or press |
  | `screen: the payment link has no QR code:` | the payment sheet, when the link does not fit a QR code (not an `Err`: the QR encoder's message) | each rebuild of that step |

  Misuse (a call before `Configure`, a ConfigError code, a call outside the subsystem's lifetime or off the game thread, a node without a game instance) is `scfg: <message>` without a heading, once per call; warnings (a dropped record, an unready route, no viewport for the sheet) are `scfg: <message>` at `Warning`. The worker's and the store's own default, used only without an `OnError` (never under the facade), is `scfg: <Err::str()>`. Nothing in the glue crashes the game: misuse is a log line and a Failed result.

### Configuration without code

`UScfgSettings` (`Public/ScfgSettings.h`) is the project settings page Project Settings > Plugins > SCFG, saved to the project's `Config/DefaultGame.ini` (section `[/Script/Scfg.ScfgSettings]`): `Options` (Configure's options; testnet starts on), `Chains` (each a key and an `FScfgChain`) and `Items` (each an id and the item's fields). Code stays the source of truth (spec, Configuration; Unity's SCFG Settings asset is the twin):

- **Applied at start, opt-in.** `UScfgSubsystem::Initialize` applies the class default through the same calls a game makes: `AddChain` for each chain, `Configure(Options)`, `AddItem` for each item (`FScfgFacade::ApplySettings`). Settings without a wallet (`Wallet` and `SolanaWallet` blank) are not applied at all, so a game configured from code is unaffected; if they have chain or item rows, one warning says why. A failing row is logged as every misuse is, then once more naming the settings (`scfg: the SCFG settings (Project Settings > Plugins > SCFG) were not applied (address.invalid). - **A code call made after it wins**, as in Unity: the settings are one unit. A `Configure` from code replaces everything they applied (options, logo, chains, items) and sees only the chains the code added itself; one that fails leaves the settings in place. An `AddChain` from code sets the settings aside (with a warning: call `Configure` next); once payments have started with them it is refused (`configure.after_add_chain`). An `AddItem` from code adds to the settings' configuration. Payments start on the first frame after a configuration, so override the settings before it, in the game instance's `Init` (after `Super::Init`) or the first level's `BeginPlay`; later, `Configure` is `configure.after_start`.

The panel's Validate button (the `ScfgEditor` module's details customization: a `UFUNCTION(CallInEditor)` button would not show, since Project Settings edits the class default and the details panel drops those buttons for an archetype, `ObjectDetails.cpp`) shows the result as a notification and on a new page of the Message Log's "SCFG" log: one error line per problem (`item.invalid_price: item "chapter2": ...`), else "Valid: ...", and a warning when the settings are not applied or use the test networks.

## Error model

The core never throws or catches: the lints forbid `throw`, `try` and `catch`. The CMake build and Unreal's game builds compile it with `-fno-exceptions`; Unreal's editor builds compile it with `-fexceptions` (see [Under UBT](#under-ubt)), so a throwing standard-library call would unwind into engine frames there, or abort in `unhandled_exception()` inside a coroutine, where elsewhere it aborts at the throw: a crash either way. Every function that can raise in Python returns a `Result<T>` (`Result.h`) holding either its value or an `Err` (`Err.h`). `Status` is `Result<void>`, and `scfg::ok()` is Python's `return None`. The caller propagates the error with `SCFG_TRY(T x, f())`, `SCFG_TRY_VOID(f())` or, in a coroutine, `SCFG_CO_TRY(T x, co_await f())`, or handles it where Python has an `except`. `Result`, `Co` and `Future` are `[[nodiscard]]`. Reading the alternative a `Result` does not hold (`value()` of an error) is a programming error: it prints what happened and aborts.

`Err::kind` is the Python class name, and `is_a()` follows Python's class tree (`Err.cpp`, after `err.gd`'s table). `except ValueError` is `e.is_a("ValueError")`, which also holds for a `ConfigError`, and a `CancelledError` is a `BaseException` that `except Exception` does not catch. The tree has Python's built-ins, the decimal signals, and `errors.py`'s classes with their stable codes (`ConfigError(code)`, `RestoreError(code)`). Also: `RpcError` keeps the JSON-RPC code and the URL, and `TransportError` keeps the HTTP status. An unknown kind given to `Err::make` or `is_a` is recorded in `errors::misuse()`, which the tests check is empty. Tier 1's `"invalid"` expectation passes only for a `ValueError` or `TypeError` that is not a `ConfigError`.

Inputs stay loosely typed as in Python. `build_config`, `build_chain`, `add_item` and `Engine::start_session` take a `Json` dict of Python's keyword arguments, and an unknown key is a `TypeError`. JSON integers are `int64_t` until they need more, then `BigInt` (unbounded, as Python's `int`). Floats are `double`. Dicts keep insertion order.

## Async rules

Python's core is generators: a function that needs the network yields a `Request`. Here such a function returns `Co<T>` (`Co.h`), and the injected `coio::Transport` hands out a `Future<Json>` that the host completes later through its `Promise` (an HTTP callback, a later tick). The core never performs a request, never blocks and never schedules anything.

- No threads, no clocks and no randomness of its own (the lints). The Engine's clock and its `Entropy` are injected. The only exceptions are `Rpc.cpp`'s default monotonic clock and `Entropy.cpp`'s default system source.
- `Co<T>` starts eagerly: the body runs inside the call until its first real suspension, and a finished callee resumes its caller by symmetric transfer. `co_await` of a `Co<T>` gives the `Result<T>` it `co_return`ed. Destroying an unfinished `Co` destroys its frame, which is cancellation.
- `Job<T>` keeps a root coroutine alive for a caller outside coroutines (the driver, the tests, the future glue), as Python's `run_sync` drives a generator. Destroying the `Job` cancels the root.
- A `Promise` destroyed without being completed completes its `Future` with `CancelledError`. Completing it twice is a programming error.
- Coroutine parameters are taken by value. A reference, `string_view`, span or pointer would dangle after the first suspension (`LintTests.CoroutineParamsByValue`).
- No coroutine lambdas, in the core or the tests (ruling R8, `LintTests.NoCoroutineLambdas`). Clang miscompiles some of them (llvm/llvm-project#91983), so coroutines are named functions with default-constructible promises.
- `Co<void>` ends with `co_return scfg::ok();`, since flowing off the end of a coroutine is undefined.
- Teardown order: destroy every `Job` (and every `Co` outside one) before the objects its coroutines use: the Engine, the RPC clients and the transport. A transport destroyed first drops its promises, and each one resumes its waiter with `CancelledError` inside the destructor, on objects that are being torn down. Destroying the Engine before a suspended `Job` is safe too (N1: a command's busy guard shares the Engine's flag through a `shared_ptr`, `EngineTests.DestroyingTheEngineBeforeASuspendedJobIsSafe`, and `DestroyingTheEngineAtEverySuspensionIsSafe` at every suspension of every networked step of every Tier 2 vector, through `tier2::destroy_engine_while_suspended`), as long as the `Job` is destroyed before its request is answered or dropped.
- g++ 13.3 has an internal compiler error on a braced initializer list inside a `co_await`'s operand. Build the argument in a local first (`Json params = Json::list({a, b}); co_await call(m, params);`).

## Lints

`core-tests/LintTests.cpp` scans every file under `Plugins/Scfg/Source/ScfgCore/` (not `ScfgCoreTests/`, whose files are Unreal code by design: the runner code it compiles lives in `core-tests/`, and UBT itself refuses two sources of one module with the same file name) and fails with `path:line: rule (why)`. Its rule tables are the source of truth. The file-level checks are in `core-tests/support/Lint.cpp`. Comments and the contents of string and char literals are ignored. `RulesBite` and `FileChecksBite` feed every rule an offending and a clean input. The rules are:

| Group | Forbidden |
|---|---|
| Exceptions and RTTI | `throw`, `try`, `catch`, `std::exception`, `dynamic_cast`, `typeid` |
| Threads and clocks | `<thread>`, `<mutex>`, `<future>`, `<condition_variable>` and the other thread headers, `std::thread`, `std::async`, `sleep` and relatives, `<chrono>`, `<ctime>`, the `std::chrono` clocks, `time()`, `rand()`, `<random>`, `random_device` |
| Locale | `<locale>`, the iostream and stringstream headers, `<regex>`, `<cctype>` and the `is*`/`to*` character functions, `<cstdio>`, `to_string`, `sto*`, `strto*`, `ato*`, `printf`, `scanf`, `puts`, `setlocale` and relatives. Python's string rules come from `scfg::py` instead |
| Portable types | `long` (32 bits on Windows), `__int128` (not on MSVC), `wchar_t` and `std::wstring`; every header needs `#pragma once` |
| Unity build | `namespace {` and `static` at namespace scope in a `.cpp`: Unreal's unity build puts every `.cpp` in one translation unit, so file-local names go in a named `detail` namespace |
| Coroutines | A `Co<T>` parameter that is a reference, view or pointer; a coroutine lambda (the tests too) |
| Files | An include that is neither standard C++20 nor `Scfg/<x>.h` (except in `Private/ScfgCoreModule.cpp`, below); a first comment that names no existing Python twin (or "No Python twin"); two basenames that differ only in case |
| Exports | In a public header: a non-inline free function, friend function or extern variable without `SCFGCORE_API`; a non-template class with a member defined in a `.cpp` without `SCFGCORE_API`; `SCFGCORE_API` without `#include "Scfg/Export.h"` (`ExportsMarked`, a heuristic scanner; `ExportsBite`) |

A file is exempt from a line rule only through `kWaivers` in `LintTests.cpp` (ruling R3), which names the file and the one rule it needs, for example `PyFloat.cpp` with `printf` and `strto*` for the shortest float repr. The one file exempt from `OnlyStdIncludes` is `Private/ScfgCoreModule.cpp`, the module's registration with Unreal, and `ModuleFileIsMinimal` holds it to exactly its two lines: `#include "Modules/ModuleManager.h"` and `IMPLEMENT_MODULE(FDefaultModuleImpl, ScfgCore)`.

Two compile-only targets check the core as Unreal will build it, and one link check its exports:

- `scfg_core_poisoned` compiles every source and every public header on its own, with `core-tests/support/UnrealMacroPoison.h` force-included. That header defines the plain words that Unreal and the Windows headers `#define` (`check`, `ERROR`, `TEXT` and others) as poison tokens, so a core name that spells one fails to compile.
- `scfg_core_unity` compiles the whole core as one translation unit, as UBT's unity build does.
- `scfg_core_shared` is the core as a shared library with `-fvisibility=hidden` and `SCFGCORE_API` defined as `__attribute__((visibility("default")))`, stricter than UBT's `-fvisibility-ms-compat`, and `scfg_core_exports` (`core-exports/Main.cpp`) links against it.

## Locale reruns and the deferred replay

- `LocaleTests` replays Tier 1 (every topic) and Tier 2 (every vector) again under `tr_TR.UTF-8`, for the dotted and dotless i, and under `de_DE.UTF-8`, for the decimal comma (`core-tests/support/Locales.h`). It sets `setlocale` and `std::locale::global`, and counts what it replayed. Without either locale it falls back to another installed one with a decimal comma. With no such locale at all the test fails (remedy: `sudo locale-gen tr_TR.UTF-8 de_DE.UTF-8`), and under `SCFG_REQUIRE_LOCALES=1` a missing named one fails it too.
- `Tier2Deferred` replays every Tier 2 vector a second time with a transport that completes requests only from the runner's pump loop, one per turn, as Unreal's HTTP callbacks complete them on a later tick. Every networked step must suspend and resume correctly from the pump. A step that leaves a request unanswered fails. This plays the role of the C# port's `Tier2SingleThreadTest`.

## Known divergences from Python

Deliberate or accepted differences. Most are reachable only with data that breaks the schema, or a node or a caller that misbehaves; the rows on a cancelled checkout or restore command and on destroying a `CheckoutController` are reached in normal operation (the worker stops, a screen goes away), and are deliberate. Python here is the reference's 3.9: messages follow CPython 3.9 where 3.12 changed them.

| Area | C++ | Python |
|---|---|---|
| Deep JSON from a node | Nesting up to exactly 1000 levels is read; deeper is a `ValueError`, so the transport reports `TransportError("invalid JSON response")` | `RecursionError` near the recursion limit, a little below 1000 (from a top-level call 995 levels parse and 996 fail; inside the transport's call stack fewer), and it escapes `UrllibTransport`, since it is not a `ValueError`. A response nested between those depths parses here and raises in Python |
| Huge amounts | `amounts::decode` of 10\*\*32 units or more is `InvalidOperation`, at any size, and restore skips it as one internal error | `decimal.Overflow` from about 10\*\*1000006 units, which `restore_lookup`'s `except InvalidOperation` does not catch. A uint256 never reaches it |
| Non-ASCII hashes | `tx_hash`, `block_hash`, receipt keys and `get_block_hash` are lowered with `py::lower_for_ascii`: exact for ASCII and for any comparison with ASCII text, but non-ASCII letters other than U+0130 and U+212A keep their case. A hostile node's non-ASCII hash can only fail safe | `str.lower()` |
| Transfer log topics | A dict as topic[1] or topic[2] is `TypeError: unhashable type: 'slice'` | The same on 3.9; 3.12 raises `KeyError` |
| Explorer templates | `py::format1` refuses format specs, indexing and attribute access. An `explorer_tx` whose only `{}` is inside an escaped `{{}}` and which also has a field such as `{:>5}` or `{.x}` is `chain.bad_explorer_tx_braces` | Accepts the first, or raises `AttributeError` for `{.x}` |
| Text colour | `text_on` computes the WCAG contrast with `std::pow` in doubles. A libm whose `pow` differs from CPython's in the last ulp could flip only an exact tie | CPython's `**` |
| Hand-built tokens | A `Token` built without `Token::make`, with `log_decimals < decimals`, is a `ValueError` when a transfer is scaled | Every `Token` runs `__post_init__`, which refuses it. One that skipped it would divide by a float |
| Entropy | `token_bytes` / `token_hex` with a negative `n` give no bytes. Every caller passes a constant | `ValueError` |
| Session order | `list_sessions` refuses list `created_at` keys, and puts a NaN after every number | Orders lists lexicographically. A NaN's place depends on which pairs timsort compares |
| Session extra fields | `create_session` with a truthy `extra` that is not a dict is a `TypeError` | Depends on the iterable: a list of pairs is merged, a str is the `ValueError` of `dict.update`, an int a `TypeError` |
| Engine stores | `Engine`'s `pending` and `receipts` must be None, falsy or dicts; anything else aborts the constructor, which cannot return an `Err`, and is a `TypeError` from `Engine::make`, which the glue uses for stores read from a file. A backend's `advance` given a non-dict store is a `TypeError` (the Engine never passes one) | `dict(x)` also takes a list of pairs, else `TypeError` or `ValueError`. A non-dict store is the `AttributeError` of `.get` |
| Engine config | The `Engine` keeps its own copy of the `Config`; an item added after it was built reaches it through `Engine::add_item` (`config::add_item` on that copy; the facade calls it through the worker) | The Engine holds the game's `Config` object itself, so a later `config.add_item` is seen at once |
| Unset `on_error` | `_advance` and `check_ready` report a contained error through `report()`: `on_error`, or `print_error` when it is unset | Call `self.on_error(e)` directly, so a handler set to None afterwards is a `TypeError` |
| RPC error codes | A JSON-RPC error code beyond int64 is kept as no code (it equals none the core compares with); the message is kept | Keeps the int, and `str(e)` is `"<code>: <message>"` |
| HTTP status | `Err::status` is empty for a status beyond `int`; the message keeps every digit | Keeps the int |
| Comparisons | `py::compare` refuses to order two lists. The core only ever compares a stored value with a number | Orders lists item by item |
| Solana account order | A NaN `accountIndex` is ordered last | Its place depends on the set's hash order |
| Transfer equality | `Transfer::operator==` compares fields with Python's `==`, so a NaN `log_index` never equals itself | Tuple comparison checks identity first, so the same NaN object equals itself |
| Error messages | The class always matches Python's, and the vectors compare only classes and codes. Some texts differ. A `sorted()` or `list_sessions` `TypeError` may name a different pair of types. Two `TypeError`s lack CPython's `scfg_core.config.` / `scfg_core.payments.` prefix. A keyword that repeats a positional argument says "unexpected keyword argument". Adjacent lone surrogates are reported as one position, and a `UnicodeEncodeError` is reported as its base class `ValueError` | CPython's own texts and classes |
| QR segments | `QrSegment::make` takes `std::vector<bool>`, so a bit other than 0 or 1 cannot be passed. Of the internal `assert`s, only the reachable codeword-count check is ported, as an `AssertionError` | Takes any ints, and fails later in `bytearray` |
| Unprintable keys | A `KeyError` for a key whose `repr` raises (an int of more than 4300 digits) has the message `<unprintable KeyError object>`, which is what `print_error` writes for it | The `KeyError` holds the key, and `str(e)` raises the `ValueError` |
| JSON values (programming errors) | `deep_copy` copies a list or dict met twice twice, and a cycle aborts `dumps` and `deep_copy`. `py::repr` prints an unassigned code point as it is | `deepcopy`'s memo keeps the aliasing; `dumps` raises `ValueError` on a cycle; `repr` escapes unassigned code points |
| Restore candidates read back (runner and driver) | `candidate_from_json` types the candidate's fields (strs, ints, a bool), except a Solana transfer's `sender`, `tx_hash` and `log_index`, which carry any value. A wrong type is a `TypeError` | The dataclass carries any value |
| Stored pending records (`FScfgStore`) | Each pending record of `state.json` is checked against the frozen schema when the file is read; a bad one is dropped with a warning (Restore brings its payment back) after the whole file was copied aside, and the cleaned stores are saved | Godot's `store.gd`, the glue's reference, checks only the file's shape: a bad record reaches the Engine, and every tick fails on it |
| HTTP timeouts (`FScfgHttpTransport`) | `SetTimeout(timeout)` bounds the whole request, so an answer that trickles in for longer than `timeout` is `TransportError("timed out")`. A `timeout` <= 0 sets no total timeout. The engine's `[HTTP] HttpConnectionTimeout` and `HttpActivityTimeout` (30 s) also end a slower connect, or a longer silence, whatever the core's timeout (the core's is 10 s) | urllib's `timeout` bounds each socket operation, and 0 fails at once |
| Checkout: started session (`Checkout.h`) | `poll()` accepts a started session only when it is a dict with a str `id`, an int `units` and, on Solana, a str `reference`; anything else is `start_failed`, and the session such a start may have created is not discarded | Keeps whatever the future held and fails later when it reads it |
| Checkout: cancelled start | A start the worker cancelled (`CancelledError`) is `start_failed` in `poll()`, as any failed start | `fut.exception()` raises `CancelledError` out of `poll()` |
| Checkout: config read once | `enabled_chains(config)`, `config.methods` and `text_on(accent)` are read once, in `CheckoutController::make()` (the controller's config cannot change), so their errors come from `make()` | Re-reads the config on every call and raises where it reads it |
| Checkout: browser page | An Err of any kind from the server factory or `Server::start()` makes the browser method unavailable; the controller drops the Err, so the server logs it itself | Catches `Exception` |
| Checkout: missing token or RPC url | `token_address()` is None for a chain without the payment's token; the page's `rpc_url` is None for a chain without RPC urls | `KeyError`; `IndexError` |
| Checkout: destruction | Destroying a `CheckoutController` closes it: a start in flight is discarded once it finishes, the page server is stopped | No `__del__`: the screen calls `cancel()` or `finish()` |
| Restore: commands (`RestoreFlow.h`) | A cancelled lookup or save is `"failed"`; a `restore_apply` success that is not a list of dicts is `"failed"` | `CancelledError` escapes `poll()`; any value is stored as `added` |
| Localhost server (`LocalServer.h`) | HTTP as `local_server.gd` reads it: a two-word (HTTP/0.9) request line is a 400, a bad request line gets a status line, the 501's body is plain text, `Expect: 100-continue` is not answered, every answer is HTTP/1.1 with `Connection: close`; a connection has `DEADLINE_S` (10 s) to send its request and again to take its answer, at most 32 are open, a head is at most 256 KiB; a `/build` result that is not a dict is a 503 | `http.server` answers HTTP/0.9 requests and bad request lines with a bare error page, an HTML 501, `100 Continue`; no deadlines or caps but `MAX_LINE` per line and 100 header lines; any JSON value as the build's result |
| Localhost server: odd input | A version such as `HTTP/+1.1` is a 400 (its numbers must be ASCII digits); a body nested deeper than 1000 lists or dicts (`json::loads`'s `MAX_DEPTH`) is a 400 | Python 3.9's `http.server` answers `HTTP/+1.1` with 200 (`int("+1")`; newer CPython answers 400); a 4000-deep body raises `RecursionError` in the handler thread, which closes without an answer |
| Localhost server: slow clients | A known local-only limit, shared with Godot: 32 connections that send partial requests hold every slot until their 10 s deadline, so the page waits (a process that reconnects every 10 s starves it). Only a local process can do this (a web page cannot send partial requests); QR and manual payment keep working | The threaded server answers every connection at once |
| Localhost server: a build the page stopped waiting for | The CheckoutController's build command cannot be withdrawn (the Submitter has no cancel): after `build_timeout_s` the page gets its 503 and the command's result is dropped when it comes | `fut.cancel()` withdraws a build the worker has not started |
| Integration driver (test-only) | `PosixHttpTransport`'s timeout bounds the whole request. A malformed status line, a short body or a bad Content-Length is a `TransportError`. A blank input line gets no reply (as in the C# driver) | The socket timeout applies to each blocking operation. `http.client` raises its own exceptions, which `UrllibTransport` does not catch |

# unreal

The C++ port of the payment core (`ScfgCore`), the start of the Unreal port. It is in development: there is no facade, UI or release yet. What exists is the engine-independent core in plain C++20, its tests and the driver for the integration tests, and the `Scfg` plugin that builds the core as its `ScfgCore` module under Unreal Build Tool, with a development project (see [Under UBT](#under-ubt)), and the start of the Unreal glue, the `Scfg` module: the worker, the HTTP transport and the UTF-8 bridge (see [The glue module](#the-glue-module)). Apart from that module's one registration file, nothing in the core includes an Unreal header. The Python core (`plugin/game/python-packages/scfg_core/`) is the reference, and the C# port (`unity/`) is the closest template. The core replays every conformance vector in `conformance/vectors/`.

## Layout

| Path | Contents |

## Development

Needs CMake 3.25 or newer, Ninja and a C++20 compiler (g++ 13, or Clang with libc++ for the `clang-libcxx` preset).

```bash
cd unreal
cmake --preset release && cmake --build --preset release && ctest --preset release   # -O2, assertions kept
cmake --preset asan && cmake --build --preset asan && ctest --preset asan            # AddressSanitizer + UBSan, -funsigned-char
cmake --preset clang-libcxx && cmake --build --preset clang-libcxx && ctest --preset clang-libcxx   # clang++ -stdlib=libc++

# one group or one test while iterating (ctest runs one test per group)
build/release/scfg_core_tests --list
build/release/scfg_core_tests --group EngineTests
build/release/scfg_core_tests --test Tier1.amounts
build/release/scfg_core_tests --test Tier2.smoke/evm_unlock_paid

# the driver against local chains (anvil / solana-test-validator on PATH), from the repository root
uv run pytest -m integration tests/integration/test_cpp_core.py
```

Every preset builds with `-Werror`, and no ctest group may fail or skip; ctest also runs `SharedLibraryExports`. A new test group must be added to `SCFG_TEST_GROUPS` in `CMakeLists.txt`, or `RunnerTests.EveryGroupIsRegistered` fails. `RunnerTests.NothingLeftOut` checks that no vector, topic or test is filtered out.

Environment:

- `SCFG_VECTORS` overrides the vectors directory the tests read (default: `conformance/vectors/`), in the CMake binary and in the editor's `Scfg.Core.*` tests (whose default is the `conformance/vectors` found by walking up from the plugin's folder).
- `SCFG_REQUIRE_LOCALES=1` (set in CI) makes `LocaleTests` fail when `tr_TR.UTF-8` or `de_DE.UTF-8` is not installed. Without it, the reruns fall back to another installed locale with a decimal comma. When there is none either (a stock Ubuntu, Docker or WSL image has only `C`, `POSIX` and `en_US`), `LocaleTests` fails. Install the two locales with `sudo locale-gen tr_TR.UTF-8 de_DE.UTF-8` (Debian: enable them in `/etc/locale.gen` first).
- `SCFG_REQUIRE_CPP=1` (set in CI) makes the `test_cpp_core.py` twins fail, rather than skip, when the toolchain is missing or unusable. `tests/integration/cpp_driver.py` builds the driver once per session into `unreal/build/integration`. It takes cmake from `PATH` or `~/.local/bin` and needs 3.25 or newer. The compiler is `$CXX` when its program resolves, else `c++`, `g++` or `clang++`. It builds with Ninja, or with make when there is no Ninja. Without one of these the twins skip. A configure or compile failure of the code itself always fails. The EVM and Arc twins also need `anvil`, which CI installs.

## Under UBT

The plugin is `Plugins/Scfg/`: `Scfg.uplugin` (version 0.3.0, `EngineVersion` 5.8.0, no content) with four modules so far, each `LoadingPhase` `Default` on Win64, Mac and Linux: `ScfgCore` and the glue `Scfg` (`Runtime`), and the test-only `ScfgCoreTests` and `ScfgTests` (`UncookedOnly`: built into the editor and uncooked targets, never into a cooked game; ModuleDescriptor.cs:792, where `DeveloperTool` would follow `bBuildDeveloperTools`, true for Development games). Only UE 5.8 (5.8.4 on Linux) has been built against; 5.6 and 5.7 are unverified.

Building, from the repository root (headless; `--engine` defaults to `$UE_ROOT`, else `/mnt/files/UnrealEngine`):

```bash
python tools/run_unreal_build.py --target ScfgDevEditor --config Development      # the editor (modular)
python tools/run_unreal_build.py --target ScfgDevEditor --config Development -- -DisableUnity   # no unity files
python tools/run_unreal_build.py --target ScfgDev --config Shipping               # a packaged game (monolithic)
```

The wrapper runs `Engine/Build/BatchFiles/Linux/Build.sh <target> Linux <config> -Project=<uproject> -WaitMutex -NoHotReload -UBAHost=127.0.0.1` (UBT's build accelerator otherwise listens on 0.0.0.0:1345) under a timeout (default an hour; on expiry, or when the wrapper gets SIGTERM, SIGINT or SIGHUP (its handlers are in before UBT starts), it kills UBT's whole process group, even when only a descendant of `Build.sh` is left) and fails when UBT fails or prints any `warning:` or `error:` line other than one located in an engine file and reached through engine files only: a warning in an engine header that our code triggers fails the build, and so does any UBT message, which names no file. A game target (any not named `*Editor`) also fails unless its link inputs (`Intermediate/Build/Linux/x64/<target>/<config>/<binary>.rsp`; a monolithic receipt lists no modules) hold a `ScfgCore` object and none of `ScfgCoreTests` or `ScfgTests`, so a test module can never ship unnoticed. Both targets set `bWarningsAsErrors = true`. The engine is an installed build, so they share its build environment, and UBT refuses a changed setting there unless `bOverrideBuildEnvironment = true`, which they also set: the override only reaches the modules UBT compiles here, which are ours. Products land in `Project/ScfgDev/Binaries/Linux/` (`libUnrealEditor-ScfgCore.so`, `libUnrealEditor-ScfgDev.so`, `ScfgDev-Linux-Shipping`) and intermediates in `Project/ScfgDev/Intermediate/` (the plugin's under `Intermediate/External/`), all gitignored; the plugin folder gets none. The project's `Config/` is committed (`DefaultEngine.ini`, empty for now, `DefaultInput.ini` as the 5.8 editor writes it, and `DefaultEditorSettings.ini`, which turns off the editor's usage analytics and the unattended crash report upload, both on in `BaseEditorSettings.ini`; `ScfgDev.NoTelemetry` checks them), so a local ini cannot change a build or a test run unnoticed; the project disables the `AndroidFileServer` plugin, whose editor module otherwise writes a random `SecurityToken` into `DefaultEngine.ini` on the first run.

`ScfgDev.Smoke` is a smoke test in the development project's module: it calls `scfg::amounts::parse_amount` from another module, which proves the core links and runs inside the editor process. Run by hand, the editor needs the three switches `run_unreal_tests.py` passes (see below): `-notraceserver`, `-NoZenAutoLaunch` and `-ddc=InstalledNoZenLocalFallback` (`NoZenLocalFallback` on a source engine), or it starts a trace server and a zen DDC service that listen on every interface.

```bash
"$UE_ROOT/Engine/Binaries/Linux/UnrealEditor-Cmd" "$PWD/unreal/Project/ScfgDev/ScfgDev.uproject" -ExecCmds="Automation RunTests ScfgDev.Smoke;Quit" \
  -unattended -nullrhi -nosplash -stdout -notraceserver -NoZenAutoLaunch -ddc=InstalledNoZenLocalFallback -ReportExportPath=<dir>
# or: python tools/run_unreal_tests.py --filter ScfgDev.Smoke
```

The conformance vectors run inside the editor process too, through `ScfgCoreTests`, by the same runner code as the CMake binary (one copy: `core-tests/tier1/` is a source directory of the module through `ConditionalAddModuleDirectory`, so a new topic file needs no edit; the five runner files of `core-tests/support/` that it needs, `Tier1`, `Tier2`, `JsonEq`, `ConfigJson` and `Vectors`, come in through one-line shims in `Private/CoreTests/`, because UBT can only add whole directories and that one also holds the CMake-only `Test.cpp`, `Lint.cpp` and `Locales.cpp`). `Private/ScfgCoreAutomationTests.cpp` turns them into automation tests (`IMPLEMENT_COMPLEX_AUTOMATION_TEST`, `EditorContext | EngineFilter`), enumerated from the vector files at run time:

| Test | What |
|---|---|
| `Scfg.Core.Tier1.<topic>` | one per `conformance/vectors/tier1/*.json` (18) |
| `Scfg.Core.Tier2.<group>.<name>` | one per `tier2/<group>/<name>.json` (121; the id's `/` is a `.` in the name), immediate transport |
| `Scfg.Core.Tier2Deferred.<group>.<name>` | the same vectors, requests answered one per pump turn |
| `Scfg.Core.NothingLeftOut` | the vector files, listed again through the engine's file manager, and the tests each complex test generates are the same names (no count is pinned, as in the CMake `RunnerTests.NothingLeftOut`), and the registered Tier 1 topics are the topic files |

```bash
python tools/run_unreal_tests.py --filter Scfg.Core   # builds ScfgDevEditor first, then runs the editor headless
python tools/run_unreal_tests.py --filter Scfg        # everything: Scfg.Core, Scfg.Glue and the dev project's ScfgDev.*
# --expect N: fail unless at least N tests passed (a minimum; today 261 for Scfg.Core, 309 for Scfg)
```

`tools/run_unreal_tests.py` builds the editor target through `run_unreal_build.py`, then runs `UnrealEditor-Cmd <uproject> -ExecCmds="Automation RunTests <filter>;Quit" -unattended -nullrhi -nosplash -stdout -notraceserver -NoZenAutoLaunch -ddc=InstalledNoZenLocalFallback -ReportExportPath=<dir>` (`NoZenLocalFallback` on a source engine) under a timeout (default 1800 s; on expiry, SIGTERM, SIGINT or SIGHUP it kills the editor's process group), reads `<dir>/index.json` (UTF-8 with a BOM) and prints `<n> passed, <m> failed`; it fails unless the editor exited 0, m is 0, no test was left unrun or in process, every entry of the report's `tests` list succeeded and their number is n, n > 0 and n reaches `--expect`. It prints which vectors the tests read (from `NothingLeftOut`'s log entry) and whether `$SCFG_VECTORS` chose them. Locale reruns stay CMake-only: inside the editor `setlocale(LC_ALL, nullptr)` is `"C"` (`NothingLeftOut` logs it).

What a test run opens on the network, measured with `ss -tunap` (listeners, outbound connections and DNS sockets of the editor's session) sampled during a run: only the editor's trace control port, `0.0.0.0:1985`, an accepted exposure, and the tests' own loopback sockets. TraceLog compiles that listener in under `TRACE_PRIVATE_ALLOW_TCP_CONTROL` (`TraceLog/Private/Trace/Control.cpp:18`, `Trace/Config.h:82-84`), starts it unconditionally (`Writer.cpp:1050`) and binds it to every interface (`Detail/Unix/UnixTrace.cpp:171-175`); no command-line switch turns it off (`-trace=`, `-tracehost=`, `-notrace*` do not touch it), so only a source-engine build could. Everything else is kept off:

- `-notraceserver` (`TraceAuxiliary.cpp:2365`): no UnrealTraceServer daemon is forked (it would outlive the run with ports 1981/1989).
- `-NoZenAutoLaunch` (`ZenServerInterface.cpp:1753`) and a DDC graph without `ZenLocal` (the file cache instead): the editor neither launches nor restarts the per-user zen DDC service. Auto-launch would listen on every interface (`*:8558`: `BaseEngine.ini` sets `[Zen.AutoLaunch] RemoteNetworkService=GeneratedStaticKey`, and only `None` adds `--http-forceloopback`, `ZenServerInterface.cpp:2085-2089`). Setting `None` in our `DefaultEngine.ini` instead is not safe: the service is shared per user on port 8558, and auto-launch shuts down a running instance whose command line differs from the one it wants (`:4153-4190`, `:4221-4237`), which could be another editor's. With `-NoZenAutoLaunch` the auto-launch path, its install update and its shutdowns are skipped entirely (`:2852`). The tests need no DDC.
- The project disables the `UdpMessaging` plugin, whose transport otherwise binds `0.0.0.0` and joins the multicast group 230.0.0.1:6666 on every interface; the in-process automation controller does not need it.
- The `ValidatePlatforms` UBT run the editor starts inherits the 1985 socket for its few seconds; UBT builds pass `-UBAHost=127.0.0.1`.
- `Scfg.Glue.Http.*` serve their JSON-RPC node on `127.0.0.1:<random port>` (`HTTPServer` binds the loopback address for `localhost`, `HttpListener.cpp:68-70`), and post only to it and to `127.0.0.1:1` (refused).
- Nothing goes to Epic: the project's `DefaultEditorSettings.ini` turns off the editor's usage analytics (`AnalyticsET` to `datarouter.ol.epicgames.com`, on by default) and the crash report upload of an unattended run that crashes (CrashReportClient, also on by default). The per-user `~/.config/Epic/UnrealEngine/5.8/Saved/Config/LinuxEditor/EditorSettings.ini`, shared by every 5.8 project, would override them; it holds neither key here, and `ScfgDev.NoTelemetry` would catch one.
- Nothing goes to Google: the editor's Home panel checks the internet connection with a GET of `https://www.google.com/generate_204` every 5 s (`SHomeScreen::CheckInternetConnection`, `MainFrame/Private/HomeScreen/SHomeScreen.cpp:939-967`, through the HTTP retry system, so no `LogHttp` line names it). The project's `DefaultEngine.ini` sets `[ConsoleVariables] HomeScreen.EnableHomeScreen=0` (a read-only cvar, `MainFrameModule.cpp:54-59`; the Home tab is then not registered, which a hand-opened editor shows too), and `ScfgDev.NoTelemetry` checks it and that no analytics provider started.

UBT caches each target's build plan (`Project/ScfgDev/Intermediate/Build/Linux/x64/<target>/<config>/Makefile.bin`) and, in 5.8, reuses it even under `-NoUBTMakefiles`, after a `.uplugin` gained a module, and when `-DisableUnity` is added or dropped: the build then silently leaves the new module out, or stays unity. `run_unreal_build.py` therefore deletes that one file before every build (a few seconds of planning).

How the core fits UBT:

- **Engine dependency.** `ScfgCore` depends on `Core`, privately, for one reason: a module needs `IMPLEMENT_MODULE(FDefaultModuleImpl, ScfgCore)`, which needs `Modules/ModuleManager.h`. That one line lives in `Private/ScfgCoreModule.cpp`, which the CMake build leaves out (`list(FILTER ...)` in `CMakeLists.txt`) and the lints exempt from `OnlyStdIncludes` only (`ModuleFileIsMinimal`). The public headers include no Unreal header, so no dependent gets `Core` through `ScfgCore`. The dependency also gives the module `Core`'s shared PCH.
- **Flags.** `PCHUsage = UseExplicitOrSharedPCHs`, no `CppStandard` override (UBT passes `-std=c++20`), `bUseRTTI` and `bEnableExceptions` left at false. Every file is compiled with `-fno-rtti`. Exceptions are on in editor builds anyway: UBT turns them on for every target compiled against the editor (`-fexceptions`), and off in game builds (`-fno-exceptions`). The core is written for either: it never throws or catches. C++20 coroutines need no flag.
- **Force-includes.** Each core file is compiled with the shared PCH of `Core` and a generated `Definitions.ScfgCore.h` force-included, so Unreal's macros (`check`, `TEXT` and the rest) are defined in every core translation unit: that is what `scfg_core_poisoned` guards against. Built with `-NoPCH -NoSharedPCH` only the definitions are force-included, and the core still builds.
- **Exports (`SCFGCORE_API`).** UBT defines `SCFGCORE_API` as `DLLEXPORT` inside the module, `DLLIMPORT` in a module that uses it (the editor build), and empty in a monolithic build. `Public/Scfg/Export.h` defines it empty outside UBT, and under UBT defines `DLLEXPORT`/`DLLIMPORT` as Unreal's platform headers do when no PCH has (the `-NoSharedPCH` build). It goes on every class with a member a `.cpp` defines (`class SCFGCORE_API Json`), every non-inline free function, every friend function such as `BigInt`'s operators (a class's export does not cover its friends) and the extern `VERSION`, never on a template, an inline function or a `constexpr` variable. Header-only classes (aggregates, interfaces with only inline or pure members) have nothing to export and carry none. Linux editor builds compile with `-fvisibility-ms-compat -fvisibility-inlines-hidden`, so a function without the macro is hidden and a call from another module fails to link. `LintTests.ExportsMarked` checks it.
- **Unity builds.** UBT's unity file `Module.ScfgCore.cpp` includes every core `.cpp` in one translation unit (`scfg_core_unity` is its CMake twin). Both targets set `bUseAdaptiveUnityBuild = false`: UBT's adaptive unity takes the files it believes are being edited out of the unity file, and it looks for `.git` only in the engine's folder, the project's and the project's parent, so here (an installed engine, the repository three levels up) it falls back to Perforce's rule and takes out every writable file, which is every file. `-DisableUnity` compiles each file alone.

## The glue module

`Plugins/Scfg/Source/Scfg/` is the Unreal side of the plugin (`Runtime`; depends on `Core` publicly, and on `CoreUObject`, `Engine`, `HTTP` and `ScfgCore` privately, so the core's headers stay out of a dependent's include path). Everything in it runs on the game thread: no threads, tasks or blocking waits, and it never hands a `scfg::Co` or `scfg::Future` to its callers. Its classes are in `Private/`; the ones the tests use carry `SCFG_API`, and `ScfgTests` adds `Scfg/Private` to its include path.

| File | What |
|---|---|
| `Public/ScfgModule.h`, `Private/ScfgModule.cpp` | `FScfgModule`, and `LogScfg` (`Private/ScfgLog.h`): every `Err` that reaches the glue is logged once there as `scfg: <Err::str()>` |
| `Private/ScfgString.h` | `ScfgString::ToUtf8` / `FromUtf8`, the one bridge between the core's UTF-8 `std::string` and `FString`, through the engine's `FTCHARToUTF8` / `FUTF8ToTCHAR`. Astral characters cross intact. Lone surrogate policy: an unpaired surrogate, and each invalid UTF-8 sequence (the core's WTF-8 form of a `\ud800` escape included), becomes one `?`, the engine's `UNICODE_BOGUS_CHAR_CODEPOINT`; the engine also turns U+FFFE and U+FFFF into `?`. An embedded NUL crosses both ways |
| `Private/ScfgTransport.h` | `FScfgTransport`: the core's `coio::Transport` plus `Shutdown()`, the last step of the teardown order Jobs, Engine, transport |
| `Private/ScfgHttpTransport.h` | `FScfgHttpTransport`, `rpc.UrllibTransport`'s twin over `FHttpModule` (game thread only; each request's delegate policy is set to `CompleteOnGameThread`): a POST with `Content-Type: application/json` and `User-Agent: scfg/0.1`, the body `json::dumps(payload)` (its `Err` fails the request at once), `SetTimeout(timeout)`. The answer completes on the game thread (the policy set on each request): an HTTP answer goes through `coio::parse_rpc_body`; no answer is a `TransportError` without a status (`timed out`, `<urlopen error connection failed>`, ...). `Shutdown()` unbinds each request's delegate before it cancels it, then drops its promise (`CancelledError`); later posts are refused |
| `Private/ScfgStore.h` | `FScfgStore`, the twin of Godot's `ScfgStore`: `FPaths::ProjectSavedDir()/Scfg/state.json` (absolute path logged once), `{"version": 1, "pending", "receipts"}`. A missing file is empty stores (a complete `state.json.tmp` is read instead when only it exists); one that exists but cannot be read (a permission, an I/O error, a directory) blocks the store (`IsBlocked()`, with its reason): no worker, no save, never overwritten. A corrupt file (not UTF-8 JSON, not an object, a version other than the int 1, a non-object `pending`/`receipts`) is moved aside to `.corrupt`, `.corrupt.2`, ... and the stores start empty; one that cannot be moved aside blocks. Each pending record is checked against `conformance/schema/state.json` (`state_schema.check`'s pending rules): a bad one is dropped with a warning after the file was copied aside, and the cleaned stores are saved; receipts are left to the core (the first reverify removes invalid ones). `CreateWorker` hands the stores to `FScfgWorker::Create` and attaches: after each `OnStateChanged` the stores are saved when their `json::dumps` text changed, atomically (`.tmp` written and fdatasync'ed, then `IFileManager::Move`, which deletes the target first: the `.tmp` fallback covers the gap). A failed save (a `dumps` Err included) keeps the old file, is reported once until a save succeeds, and is retried every 10 s from the ticker; the destructor tries once more. Errors and warnings go to `OnError`/`OnWarning` (LogScfg), once |
| `Private/ScfgWorker.h` | `FScfgWorker`, the twin of `worker.py` and `worker.gd`: it owns the transport and the Engine (made with `Engine::make`, so a stored `pending` or `receipts` that is not a dict is a `TypeError`, not an abort), takes the first `Snapshot`, and runs the commands (`StartSession`, `BuildSolanaPayment`, `ReportHint`, `SetUiStatus`, `Discard`, `Reverify`, `RestoreLookup`, `RestoreApply`, `Tick`) one at a time from a FIFO, from `FTSTicker` (the core ticker by default). A tick is coalesced (one pending at most) and yields to queued commands; every command asks for one; the clock asks every `Interval()` seconds (`POLL_INTERVAL`, `worker.py`'s 15.0) after a tick ended; the first tick runs `reverify()` first, once. Each callback runs from the ticker, never inside the call that submitted the command, after the command's Err, if any, was reported, the `Snapshot` was refreshed and `OnStateChanged` fired: the worker reports every Err (a `CancelledError` excepted) to `OnError` exactly once, callback or not, so callers must not log it again. `OnStateChanged` is a shared `FScfgStateChanged` handler list (`Add`, `AddSP`, `AddSPLambda`, `AddLambda`, `Remove`): its handlers run in order, one removed by an earlier one is skipped, and none runs once a handler has destroyed the worker; a handler binds weakly (`AddSP`) or is removed in its owner's destructor. `Stop()` cancels the running and queued commands (`CancelledError`); destroying the worker cancels without calling back and tears down Jobs, Engine, transport |

Entropy: the Engine keeps the core's `SystemEntropy` (`std::random_device`). Under UBT's bundled libc++ 20 on Linux, `random_device` is libc++'s `_LIBCPP_USING_DEV_RANDOM`: it opens `/dev/urandom` and `read()`s 4 bytes per call (checked with `strace` on a program built by the engine's clang and libc++, and in `libc++.a`'s `random.cpp.o`, which imports `open`/`read` and no `getrandom`). `token_bytes(n)` fills exactly `n` bytes from those 32-bit words, so `randbelow`'s contract holds. Apple's libc++ uses `arc4random` and MSVC's STL `rand_s`.

The tests, `Scfg.Glue.*` in `ScfgTests` (`UncookedOnly`, never in a game: `run_unreal_build.py` fails a game link that holds it):

| Test | What |
|---|---|
| `Scfg.Glue.String.RoundTrip`, `.LoneSurrogate` | the bridge both ways, astral planes and NUL included, and the `?` policy |
| `Scfg.Glue.Worker.*` (22) | `test_worker.py` and `test_worker.gd`'s behaviour with the real Engine over a fake transport that answers on a later frame, and a private `FTSTicker` each test ticks by hand: first snapshot, refused stores, reverify once (and again after a cancelled one; a failed one keeps its Err through `Stop()`), outcomes, command order, coalesced ticks, the interval, failing ticks, every Err reported once (before a handler can destroy the worker), `Stop()` (and a deferred one), `OnStateChanged` order and its removed, added and dead handlers, teardown and handlers that destroy the worker, and the receipt and Solana commands |
| `Scfg.Glue.Store.*` (16) | `test_store.gd`'s ten tests one by one (round trip with ints, the directory created, missing, corrupt shapes, a failed write, a failed rename, the `.tmp` fallback, an unreadable file, `.corrupt` then `.corrupt.2` and `.3`, a read-only directory), each in `Saved/ScfgTests/<random>`; then the schema copy against `conformance/schema/state.json`, the pending-record check, a malformed record dropped and the file kept, a round trip through the worker over a fake node (saving only what changed, either teardown order), a failed save retried every 10 s, and a `dumps` Err (an int of 4401 digits). The permission tests skip as root |
| `Scfg.Glue.Http.*` (6) | `FScfgHttpTransport` against a JSON-RPC node the test serves itself with `HTTPServer` on 127.0.0.1 (a random port): `eth_blockNumber` through an `RpcClient`, completed on the game thread; a 503, a 400 with a JSON-RPC error, a non-JSON body; a refused connection and a timeout; `Shutdown()` with a request in flight; a `dumps` Err and a request the engine will not start, both complete inside `post_json`; and the worker itself over this transport. HTTPS is not tested yet |

## Error model

The core never throws or catches: the lints forbid `throw`, `try` and `catch`. The CMake build and Unreal's game builds compile it with `-fno-exceptions`; Unreal's editor builds compile it with `-fexceptions` (see [Under UBT](#under-ubt)), so a throwing standard-library call would unwind into engine frames there, or abort in `unhandled_exception()` inside a coroutine, where elsewhere it aborts at the throw: a crash either way. Every function that can raise in Python returns a `Result<T>` (`Result.h`) holding either its value or an `Err` (`Err.h`). `Status` is `Result<void>`, and `scfg::ok()` is Python's `return None`. The caller propagates the error with `SCFG_TRY(T x, f())`, `SCFG_TRY_VOID(f())` or, in a coroutine, `SCFG_CO_TRY(T x, co_await f())`, or handles it where Python has an `except`. `Result`, `Co` and `Future` are `[[nodiscard]]`. Reading the alternative a `Result` does not hold (`value()` of an error) is a programming error: it prints what happened and aborts.

`Err::kind` is the Python class name, and `is_a()` follows Python's class tree (`Err.cpp`, after `err.gd`'s table). `except ValueError` is `e.is_a("ValueError")`, which also holds for a `ConfigError`, and a `CancelledError` is a `BaseException` that `except Exception` does not catch. The tree has Python's built-ins, the decimal signals, and `errors.py`'s classes with their stable codes (`ConfigError(code)`, `RestoreError(code)`). Also: `RpcError` keeps the JSON-RPC code and the URL, and `TransportError` keeps the HTTP status. An unknown kind given to `Err::make` or `is_a` is recorded in `errors::misuse()`, which the tests check is empty. Tier 1's `"invalid"` expectation passes only for a `ValueError` or `TypeError` that is not a `ConfigError`.

Inputs stay loosely typed as in Python. `build_config`, `build_chain`, `add_item` and `Engine::start_session` take a `Json` dict of Python's keyword arguments, and an unknown key is a `TypeError`. JSON integers are `int64_t` until they need more, then `BigInt` (unbounded, as Python's `int`). Floats are `double`. Dicts keep insertion order.

## Async rules

Python's core is generators: a function that needs the network yields a `Request`. Here such a function returns `Co<T>` (`Co.h`), and the injected `coio::Transport` hands out a `Future<Json>` that the host completes later through its `Promise` (an HTTP callback, a later tick). The core never performs a request, never blocks and never schedules anything.

- No threads, no clocks and no randomness of its own (the lints). The Engine's clock and its `Entropy` are injected. The only exceptions are `Rpc.cpp`'s default monotonic clock and `Entropy.cpp`'s default system source.
- `Co<T>` starts eagerly: the body runs inside the call until its first real suspension, and a finished callee resumes its caller by symmetric transfer. `co_await` of a `Co<T>` gives the `Result<T>` it `co_return`ed. Destroying an unfinished `Co` destroys its frame, which is cancellation.
- `Job<T>` keeps a root coroutine alive for a caller outside coroutines (the driver, the tests, the future glue), as Python's `run_sync` drives a generator. Destroying the `Job` cancels the root.
- A `Promise` destroyed without being completed completes its `Future` with `CancelledError`. Completing it twice is a programming error.
- Coroutine parameters are taken by value. A reference, `string_view`, span or pointer would dangle after the first suspension (`LintTests.CoroutineParamsByValue`).
- No coroutine lambdas, in the core or the tests (ruling R8, `LintTests.NoCoroutineLambdas`). Clang miscompiles some of them (llvm/llvm-project#91983), so coroutines are named functions with default-constructible promises.
- `Co<void>` ends with `co_return scfg::ok();`, since flowing off the end of a coroutine is undefined.
- Teardown order: destroy every `Job` (and every `Co` outside one) before the objects its coroutines use: the Engine, the RPC clients and the transport. A transport destroyed first drops its promises, and each one resumes its waiter with `CancelledError` inside the destructor, on objects that are being torn down. Destroying the Engine before a suspended `Job` is safe too (N1: a command's busy guard shares the Engine's flag through a `shared_ptr`, `EngineTests.DestroyingTheEngineBeforeASuspendedJobIsSafe`, and `DestroyingTheEngineAtEverySuspensionIsSafe` at every suspension of every networked step of every Tier 2 vector, through `tier2::destroy_engine_while_suspended`), as long as the `Job` is destroyed before its request is answered or dropped.
- g++ 13.3 has an internal compiler error on a braced initializer list inside a `co_await`'s operand. Build the argument in a local first (`Json params = Json::list({a, b}); co_await call(m, params);`).

## Lints

`core-tests/LintTests.cpp` scans every file under `Plugins/Scfg/Source/ScfgCore/` (not `ScfgCoreTests/`, whose files are Unreal code by design: the runner code it compiles lives in `core-tests/`, and UBT itself refuses two sources of one module with the same file name) and fails with `path:line: rule (why)`. Its rule tables are the source of truth. The file-level checks are in `core-tests/support/Lint.cpp`. Comments and the contents of string and char literals are ignored. `RulesBite` and `FileChecksBite` feed every rule an offending and a clean input. The rules are:

| Group | Forbidden |
|---|---|
| Exceptions and RTTI | `throw`, `try`, `catch`, `std::exception`, `dynamic_cast`, `typeid` |
| Threads and clocks | `<thread>`, `<mutex>`, `<future>`, `<condition_variable>` and the other thread headers, `std::thread`, `std::async`, `sleep` and relatives, `<chrono>`, `<ctime>`, the `std::chrono` clocks, `time()`, `rand()`, `<random>`, `random_device` |
| Locale | `<locale>`, the iostream and stringstream headers, `<regex>`, `<cctype>` and the `is*`/`to*` character functions, `<cstdio>`, `to_string`, `sto*`, `strto*`, `ato*`, `printf`, `scanf`, `puts`, `setlocale` and relatives. Python's string rules come from `scfg::py` instead |
| Portable types | `long` (32 bits on Windows), `__int128` (not on MSVC), `wchar_t` and `std::wstring`; every header needs `#pragma once` |
| Unity build | `namespace {` and `static` at namespace scope in a `.cpp`: Unreal's unity build puts every `.cpp` in one translation unit, so file-local names go in a named `detail` namespace |
| Coroutines | A `Co<T>` parameter that is a reference, view or pointer; a coroutine lambda (the tests too) |
| Files | An include that is neither standard C++20 nor `Scfg/<x>.h` (except in `Private/ScfgCoreModule.cpp`, below); a first comment that names no existing Python twin (or "No Python twin"); two basenames that differ only in case |
| Exports | In a public header: a non-inline free function, friend function or extern variable without `SCFGCORE_API`; a non-template class with a member defined in a `.cpp` without `SCFGCORE_API`; `SCFGCORE_API` without `#include "Scfg/Export.h"` (`ExportsMarked`, a heuristic scanner; `ExportsBite`) |

A file is exempt from a line rule only through `kWaivers` in `LintTests.cpp` (ruling R3), which names the file and the one rule it needs, for example `PyFloat.cpp` with `printf` and `strto*` for the shortest float repr. The one file exempt from `OnlyStdIncludes` is `Private/ScfgCoreModule.cpp`, the module's registration with Unreal, and `ModuleFileIsMinimal` holds it to exactly its two lines: `#include "Modules/ModuleManager.h"` and `IMPLEMENT_MODULE(FDefaultModuleImpl, ScfgCore)`.

Two compile-only targets check the core as Unreal will build it, and one link check its exports:

- `scfg_core_poisoned` compiles every source and every public header on its own, with `core-tests/support/UnrealMacroPoison.h` force-included. That header defines the plain words that Unreal and the Windows headers `#define` (`check`, `ERROR`, `TEXT` and others) as poison tokens, so a core name that spells one fails to compile.
- `scfg_core_unity` compiles the whole core as one translation unit, as UBT's unity build does.
- `scfg_core_shared` is the core as a shared library with `-fvisibility=hidden` and `SCFGCORE_API` defined as `__attribute__((visibility("default")))`, stricter than UBT's `-fvisibility-ms-compat`, and `scfg_core_exports` (`core-exports/Main.cpp`) links against it.

## Locale reruns and the deferred replay

- `LocaleTests` replays Tier 1 (every topic) and Tier 2 (every vector) again under `tr_TR.UTF-8`, for the dotted and dotless i, and under `de_DE.UTF-8`, for the decimal comma (`core-tests/support/Locales.h`). It sets `setlocale` and `std::locale::global`, and counts what it replayed. Without either locale it falls back to another installed one with a decimal comma. With no such locale at all the test fails (remedy: `sudo locale-gen tr_TR.UTF-8 de_DE.UTF-8`), and under `SCFG_REQUIRE_LOCALES=1` a missing named one fails it too.
- `Tier2Deferred` replays every Tier 2 vector a second time with a transport that completes requests only from the runner's pump loop, one per turn, as Unreal's HTTP callbacks complete them on a later tick. Every networked step must suspend and resume correctly from the pump. A step that leaves a request unanswered fails. This plays the role of the C# port's `Tier2SingleThreadTest`.

## Known divergences from Python

Deliberate or accepted differences. None is reachable with valid, schema-conforming data. Python here is the reference's 3.9: messages follow CPython 3.9 where 3.12 changed them.

| Area | C++ | Python |
|---|---|---|
| Deep JSON from a node | Nesting up to exactly 1000 levels is read; deeper is a `ValueError`, so the transport reports `TransportError("invalid JSON response")` | `RecursionError` near the recursion limit, a little below 1000 (from a top-level call 995 levels parse and 996 fail; inside the transport's call stack fewer), and it escapes `UrllibTransport`, since it is not a `ValueError`. A response nested between those depths parses here and raises in Python |
| Huge amounts | `amounts::decode` of 10\*\*32 units or more is `InvalidOperation`, at any size, and restore skips it as one internal error | `decimal.Overflow` from about 10\*\*1000006 units, which `restore_lookup`'s `except InvalidOperation` does not catch. A uint256 never reaches it |
| Non-ASCII hashes | `tx_hash`, `block_hash`, receipt keys and `get_block_hash` are lowered with `py::lower_for_ascii`: exact for ASCII and for any comparison with ASCII text, but non-ASCII letters other than U+0130 and U+212A keep their case. A hostile node's non-ASCII hash can only fail safe | `str.lower()` |
| Transfer log topics | A dict as topic[1] or topic[2] is `TypeError: unhashable type: 'slice'` | The same on 3.9; 3.12 raises `KeyError` |
| Explorer templates | `py::format1` refuses format specs, indexing and attribute access. An `explorer_tx` whose only `{}` is inside an escaped `{{}}` and which also has a field such as `{:>5}` or `{.x}` is `chain.bad_explorer_tx_braces` | Accepts the first, or raises `AttributeError` for `{.x}` |
| Text colour | `text_on` computes the WCAG contrast with `std::pow` in doubles. A libm whose `pow` differs from CPython's in the last ulp could flip only an exact tie | CPython's `**` |
| Hand-built tokens | A `Token` built without `Token::make`, with `log_decimals < decimals`, is a `ValueError` when a transfer is scaled | Every `Token` runs `__post_init__`, which refuses it. One that skipped it would divide by a float |
| Entropy | `token_bytes` / `token_hex` with a negative `n` give no bytes. Every caller passes a constant | `ValueError` |
| Session order | `list_sessions` refuses list `created_at` keys, and puts a NaN after every number | Orders lists lexicographically. A NaN's place depends on which pairs timsort compares |
| Session extra fields | `create_session` with a truthy `extra` that is not a dict is a `TypeError` | Depends on the iterable: a list of pairs is merged, a str is the `ValueError` of `dict.update`, an int a `TypeError` |
| Engine stores | `Engine`'s `pending` and `receipts` must be None, falsy or dicts; anything else aborts the constructor, which cannot return an `Err`, and is a `TypeError` from `Engine::make`, which the glue uses for stores read from a file. A backend's `advance` given a non-dict store is a `TypeError` (the Engine never passes one) | `dict(x)` also takes a list of pairs, else `TypeError` or `ValueError`. A non-dict store is the `AttributeError` of `.get` |
| Unset `on_error` | `_advance` and `check_ready` report a contained error through `report()`: `on_error`, or `print_error` when it is unset | Call `self.on_error(e)` directly, so a handler set to None afterwards is a `TypeError` |
| RPC error codes | A JSON-RPC error code beyond int64 is kept as no code (it equals none the core compares with); the message is kept | Keeps the int, and `str(e)` is `"<code>: <message>"` |
| HTTP status | `Err::status` is empty for a status beyond `int`; the message keeps every digit | Keeps the int |
| Comparisons | `py::compare` refuses to order two lists. The core only ever compares a stored value with a number | Orders lists item by item |
| Solana account order | A NaN `accountIndex` is ordered last | Its place depends on the set's hash order |
| Transfer equality | `Transfer::operator==` compares fields with Python's `==`, so a NaN `log_index` never equals itself | Tuple comparison checks identity first, so the same NaN object equals itself |
| Error messages | The class always matches Python's, and the vectors compare only classes and codes. Some texts differ. A `sorted()` or `list_sessions` `TypeError` may name a different pair of types. Two `TypeError`s lack CPython's `scfg_core.config.` / `scfg_core.payments.` prefix. A keyword that repeats a positional argument says "unexpected keyword argument". Adjacent lone surrogates are reported as one position, and a `UnicodeEncodeError` is reported as its base class `ValueError` | CPython's own texts and classes |
| QR segments | `QrSegment::make` takes `std::vector<bool>`, so a bit other than 0 or 1 cannot be passed. Of the internal `assert`s, only the reachable codeword-count check is ported, as an `AssertionError` | Takes any ints, and fails later in `bytearray` |
| Unprintable keys | A `KeyError` for a key whose `repr` raises (an int of more than 4300 digits) has the message `<unprintable KeyError object>`, which is what `print_error` writes for it | The `KeyError` holds the key, and `str(e)` raises the `ValueError` |
| JSON values (programming errors) | `deep_copy` copies a list or dict met twice twice, and a cycle aborts `dumps` and `deep_copy`. `py::repr` prints an unassigned code point as it is | `deepcopy`'s memo keeps the aliasing; `dumps` raises `ValueError` on a cycle; `repr` escapes unassigned code points |
| Restore candidates read back (runner and driver) | `candidate_from_json` types the candidate's fields (strs, ints, a bool), except a Solana transfer's `sender`, `tx_hash` and `log_index`, which carry any value. A wrong type is a `TypeError` | The dataclass carries any value |
| HTTP timeouts (`FScfgHttpTransport`) | `SetTimeout(timeout)` bounds the whole request, so an answer that trickles in for longer than `timeout` is `TransportError("timed out")`. A `timeout` <= 0 sets no total timeout. The engine's `[HTTP] HttpConnectionTimeout` and `HttpActivityTimeout` (30 s) also end a slower connect, or a longer silence, whatever the core's timeout (the core's is 10 s) | urllib's `timeout` bounds each socket operation, and 0 fails at once |
| Integration driver (test-only) | `PosixHttpTransport`'s timeout bounds the whole request. A malformed status line, a short body or a bad Content-Length is a `TransportError`. A blank input line gets no reply (as in the C# driver) | The socket timeout applies to each blocking operation. `http.client` raises its own exceptions, which `UrllibTransport` does not catch |

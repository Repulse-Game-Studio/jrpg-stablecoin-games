# godot

Pure-GDScript port of the payment core for Godot 4.3 and newer (`addons/scfg/core/`), the Godot glue around it (`addons/scfg/`, M4), its headless test runner (`tests/`) and the JSON-lines driver for the integration tests (`tests/integration/`). This directory is a minimal dev project that registers the `Scfg` autoload and enables the editor plugin.

## The addon

- `plugin.cfg`, `plugin.gd`: the editor plugin "Stablecoin for Games (SCFG)". Enabling it adds the autoload `Scfg` (`scfg.gd`); disabling it removes it. It is the only editor-only file.
- `scfg.gd`: the `Scfg` autoload, the twin of `plugin/game/scfg/scfg_api.rpy`. `configure(opts)`, `add_chain(key, opts)` (before `configure`) and `add_item(item_id, opts)` take Ren'Py's keyword arguments as a Dictionary and return null or the `ScfgErr` they reported with `push_error("scfg: ...")`. The queries are `owns`, `has_tipped`, `tip_total` (a decimal String), `receipts` and `pending` (Dictionaries keyed like the Engine's stores), `export_receipts`, `supported` and `clear_local_data`. Signals: `payment_resolved(result)` and `receipts_changed`. A `logo` may be given as `res://images/logo.png`.
- Payment and restore flows, on the same autoload: `await Scfg.pay(kind, {item, amount, token, callback})` and `await Scfg.restore({callback})` show their screen through `Scfg.sheet_host` and resolve with an `ScfgPaymentResult` / `ScfgRestoreResult` when the screen closes. `pay()` resolves `already_owned` at once for an owned unlock. A misused call reports with `push_error` and resolves `failed`, with the ConfigError code (or the error kind, such as `TypeError`) as `error`; it never crashes. A `callback` gets the call's own already_owned, failed or cancelled result and every later result of that payment, until the payment is over (its paid or underpaid result, or the session ending unpaid: scan horizon or a network switch), when the autoload releases it; without one, a cancel and the later results reach `payment_resolved`, even when the awaited call also returns that result (a payment confirmed while its sheet is open, a cancel), as Ren'Py's `on_result`: handlers must be idempotent. A sheet closed with `keep_playing` resolves `pending` and keeps its browser page answering until the session is final or the browser timeout passes. With `Scfg.notify` on, a confirmed payment and a restore are announced through `sheet_host.notify()`, with the Ren'Py texts through `tr()`. The worker polls every 3 s while a payment sheet or the restore screen is open, else every 15 s.
- `sheet_host.gd`: `ScfgSheetHost`, the interface between the flows and the screens: `open_payment(controller)` and `open_restore(controller)` return a Node with `signal closed(how)` (`cancel`, `keep_playing` or `finish` for the sheet), `close(node)` and `notify(text)`. A Node freed (`free()` or `queue_free()`) without emitting `closed` counts as `cancel`, noticed on the next frame; a Node taken out of the tree, reparented or never added to it is still open. When the game quits with a screen open (the autoload leaves the tree, or is freed), `pay()` and `restore()` resolve at once, `cancelled` unless a result was already final, and nothing is delivered (no callback, no `payment_resolved`, no notification), as Ren'Py's `_shutdown`; the session is not marked cancelled, so the Engine keeps watching it on the next launch. The flows close the controller, stopping its page, before they call `close(node)`. The base class shows nothing, so with it `pay()` and `restore()` resolve `failed` with `sheet.unavailable`; the autoload's default is `ScfgDefaultSheetHost` (below). The screens' buttons call the autoload's actions `open_browser(ctl)`, `open_wallet_app(ctl)` (the EIP-681 / Solana Pay link, for mobile), `open_explorer(url)`, `copy(text)` and `paste_into(ctl)` (the clipboard's first word, hash characters only, at most 90).
- `ui/`: the screens `ScfgDefaultSheetHost` (`ui/default_sheet_host.gd`, the autoload's default `sheet_host`) shows, each under its own `CanvasLayer` at layer 128, dimming the game and taking focus while open. It does not stop game nodes that read input in `_input` or poll `Input` in `_process`, so set `get_tree().paused = true` while you await `pay()` / `restore()` (the autoload and the screens run `PROCESS_MODE_ALWAYS`, and the demo does this). `ui/sheet.tscn` (`ScfgSheet`) is the payment sheet, the twin of Ren'Py's `scfg_payment`: one step at a time (amount for tips, network, method, then browser, QR or manual, then waiting, then done), each with the header (back arrow while the controller `can_go_back`, step dots, logo, title, price), a scrolling body, a pinned forward button and the footer (status message, status line, Cancel / Continue playing / Continue). Debug builds also show the DEV MODE lines. `ui/restore.tscn` (`ScfgRestoreScreen`) is the restore screen. `ui/qr_view.gd` (`ScfgQrView`) draws the core's QR matrix black on white with a quiet zone of 2 at an integer scale; `ui/toast.gd` (`ScfgToast`) shows `notify()` texts. Keyboard and gamepad: every step focuses its primary control and wires `focus_neighbor_*` so the focus stays in the screen; `ui_accept` presses the focused button, `ui_cancel` goes back (on the sheet's first step it cancels; on the restore screen it closes). The up and down arrow keys also leave a text field (a `LineEdit` would keep them), and on Godot 4.4+ a field the focus reaches starts editing at once, so typing works without pressing Enter first. The screens keep working while the game is paused, and so does the autoload's pump.
- **Customising the look** (D9), from least to most work:
  - `Scfg.configure({"logo": "res://...", "accent": "#rrggbb"})`: the logo in the header, and the accent for the selected option, the forward button, the progress and the dots. Text on the accent is white or ink, whichever `ScfgConfig.text_on` picks.
  - `Scfg.configure({"theme": my_theme})`: a `Theme` merged over the built-in Margin theme (`ui/theme.gd`, `ScfgTheme`). Your definitions win and the rest stays; your Theme itself is not changed. Style the screens through the type variations listed at the top of `ui/theme.gd` (`ScfgTitle`, `ScfgAccent`, `ScfgOption`, `ScfgSheetPanel`, ...) and the colors of the type `ScfgSheet` (`accent`, `ink`, `line`, `ok`, `warn`, `error`, `dim`), or the base types (`Label`, `Button`, `LineEdit`). Sizes in the built-in theme are scaled for the window (designed at 1280x720); yours are used as given.
  - `Scfg.configure({"sheet_scene": preload("res://my_sheet.tscn")})`: your scene replaces the payment sheet. Its root must have `func bind(controller, scfg)` and `signal closed(how)`. `bind()` is called once, before the root enters the tree, with the `ScfgCheckoutController` and the `Scfg` autoload. Show the controller's fields (`step`, `state`, `chain_options()`, `methods()`, `price_text`, `pay_amount_text`, `recipient`, `token_address`, `hint_tx`, `confirmations`/`required`, `message()`, `can_go_back`, `step_dots()` ...), call its methods (`choose_network`, `choose_method`, `next_step`, `set_tip_amount`, `mark_sent`, `submit_hash`, `back`) and the autoload's actions (`open_browser`, `open_wallet_app`, `open_explorer`, `copy`, `paste_into`); its helpers for screens are `accent()`, `logo_texture()`, `item_title(id)`, `chain_name(key)`, `is_web()`, `is_mobile()` and `receipts()`. Translate its `message()` with `tr()` when you show it, and emit `closed("cancel")`, `closed("keep_playing")` (only once a session exists) or `closed("finish")` (after a final state) once. Never call the controller's `poll()`: the autoload does. The host puts the root on a `CanvasLayer` at 128 and removes it after the controller is closed. A root without `bind` and `closed` is not shown: `pay()` resolves `failed` with `sheet.unavailable`, and the reason is reported. The restore screen is not replaced; to replace both, or to show them another way, set `Scfg.sheet_host` to your own `ScfgSheetHost`.
  - `theme` and `sheet_scene` are Godot-only `configure()` keys, checked here (a wrong type is a `TypeError`, reported) and not passed to the core.
- **Translations** (D17): every text the screens show goes through `tr()`, and the core's player messages are translated when shown (`tr(controller.message())`). `addons/scfg/translations/scfg.pot` is the template, generated by `uv run python tools/make_pot.py` from the addon's `tr("...")` calls, its `.tscn` texts and the core's messages (`conformance/vectors/messages.json` and the restore screen's `MESSAGES`); `--check` fails when it is out of date. Translate it into a `.po` file and add that under Project Settings > Localization > Translations. Item titles also go through `tr()`, so your own translations of them apply. The screens turn Godot's auto-translation off for themselves, so addresses, amounts and chain names are never translated by accident.
- `payment_result.gd`, `restore_result.gd`: `ScfgPaymentResult` and `ScfgRestoreResult`, the typed results (`from_core` builds one from the core's Dictionary).
- `local_server.gd`: `ScfgCheckoutServer`, the twin of `scfg_core/local_server.py`: the localhost page server for desktop browser wallets, a minimal HTTP/1.1 server on `TCPServer`. `ScfgCheckoutServer.new(opts)` takes `CheckoutServer`'s keyword arguments (`load_asset`, `session_info`, `on_tx`, `get_status`, `load_logo`, `build_tx`, `host`); `start()` (null or an `ScfgErr`), `stop()`, `url`, `running`, and `pump()`, which the glue calls every frame and which never waits on a socket. Same routes, status codes, headers and hardening as the Python server (exact Host header, 128-bit secret prefix, 4 KB body cap, no CORS, nosniff, raster-only logo). `/build` holds its connection until the `build_tx` job finishes, or answers 503 and cancels it after `BUILD_TIMEOUT_S`. A connection has 10 s to send its request; at most 32 are open. At most 99 header lines are read, as `http.client` counts them. Every callback is checked with `is_valid()` before it is called.
- `store.gd`: `ScfgStore`, which reads and atomically writes `user://scfg/state.json` (`{"version": 1, "pending": ..., "receipts": ...}`). A corrupt file is moved aside (`.corrupt`, then `.corrupt.2`, ...) with a warning; a file that exists but cannot be read right now (a lock, a permission, an I/O error), or a corrupt one that cannot be moved aside, is left alone, payments do not start that run (reported as unreadable stored receipts) and nothing is saved over it. A failed save is retried every 10 s and reported once, then again only after a save succeeded.
- `web_mirror.gd`: `ScfgWebMirror`, the receipts' second copy on a web export, in the page's `localStorage` under `scfg:<application/config/name>:<sha256 hex of the storage id>` (`{"version": 1, "receipts": ...}`, receipts only). `update(receipts, dropped)` reads the copy and merges into it (another tab's receipts stay; the keys this tab removed itself leave it); `write()` replaces it. Its two scripts are constant JavaScript called on JSON literals (the key and the text), and they catch every browser error, so a missing, blocked or full localStorage is a warning, never an exception. See "Web exports".

The autoload reads the state file on first use and starts the Engine and Worker on the first frame after `configure()`. Receipt changes, sessions added or removed, and a session's `state` or `hint_tx` changing are written at once. Scan progress is written at most every 10 s, and once more when the game quits. Its test hook `_setup(opts)` (store path, clocks, transport, scheduler, quiet reporting, platform, server factory) is not API.

The Python core (`plugin/game/python-packages/scfg_core/`) is the reference. Each Python module has one GDScript file at the same relative path (`scfg_core/solana/tx.py` is `addons/scfg/core/solana/tx.gd`, `class_name ScfgSolanaTx`), with the Python function and constant names. It replays every conformance vector in `conformance/vectors/` on 4.3 and on the latest stable Godot. No GDExtension, no C#, no editor-only API.

## The runner

`tests/run.gd` loads each `test_*.gd` directly in the tests directory (`--tests=<res:// dir>` picks another), runs its `test_*` methods one at a time, awaits coroutine tests, and prints `PASS`/`FAIL`/`SKIP` lines and the summary `<n> passed, <n> failed, <n> skipped`. Tests use `T` from `tests/t.gd` and must end with `return T.done()`: a runtime script error only aborts the erroring function, so a method that does not return `true` fails. A test that made no checks fails, a skip never counts as a pass, and a coroutine test pending after `--test-timeout` seconds (default 600) fails the run.

The exit code is 0 only for at least one pass and no failure. Godot itself can still exit 0 when `run.gd` cannot compile (for example a project that was never imported). `tools/run_godot_tests.py` therefore also requires the summary line with `n > 0` passed and 0 failed, and it kills and fails a run that outlasts `--timeout` seconds (default 900). CI's `godot-core` job runs it on 4.3-stable and 4.7.2-stable.

## The error model

GDScript has no exceptions. A function that Python can raise from returns **its value or an `ScfgErr`** (`addons/scfg/core/err.gd`), and its doc comment carries `## @fallible`.

- `kind` is the Python exception class name. `is_a(kind)` follows Python's class tree, so `except ValueError` is `e.is_a("ValueError")`, which also holds for a ConfigError.
- `code` is the ConfigError/RestoreError string code or the RpcError int code, else `null`. `message` is Python's `str(exc)`. `status` is the HTTP status of a TransportError.
- Every caller checks: `var v: Variant = f(); if v is ScfgErr: return v`. It can also handle the error where Python has an `except`.
- A Godot runtime error is never part of the contract. A coroutine that should have produced a value but returned `null` was aborted, and a session step treats that as a contained failure, like Python's `except Exception`.
- Constructors cannot fail, so a fallible class is built with `create()`, which returns the object or its `ScfgErr`. `ScfgEngine.new` keeps the error in `init_error`.
- Never use `assert()` for anything a caller can trigger: export builds strip it.

## Coroutine rules

- A function that does network I/O, directly or through a callee, is a coroutine, and every caller `await`s it. A missing `await` hands the caller a function state instead of the value.
- On `ScfgEngine` the coroutines are `start_session`, `build_solana_payment`, `tick`, `reverify` and `restore_lookup`. Every other method is plain.
- The transport is injected: any `RefCounted` with a coroutine `post_json(url, payload, timeout) -> Variant` (see `coio.gd`). The real one is `ScfgHttpTransport.new(host)`, whose `HTTPRequest` children live under `host`, a Node that must already be in the scene tree. A `SceneTree` script's root enters the tree only after `_initialize`, so await one frame before the first request.
- The Engine is not re-entrant. Only the single-writer `ScfgWorker` calls it, one command at a time, and the game reads its detached snapshots. A command must not `await` `run_once()`, which would deadlock.
- A lambda that awaits makes only the lambda a coroutine, not the function around it.

## Lints

`tests/test_lints.gd` scans `addons/scfg/**.gd` (the core and the glue) on every run. Its header documents the exact rules and known limits.

- **Error propagation:** every call to an `@fallible` function must be checked with `is ScfgErr` within the next two lines, returned directly from a fallible function, or waived with `# err-ok: <reason>`. A function that builds or returns an `ScfgErr` must itself be `@fallible`.
- **No unawaited coroutines:** a call to a known coroutine (found by its body, a `## @coroutine` tag, or an override of one) must be awaited on the same line.
- **No asserts** in core code.

## Numbers and JSON

`int` holds everything Python stores in state; the frozen schema keeps those values below 2^53. `ScfgBigInt` holds anything that can pass 2^63 (uint256 log values, Arc's raw 18-decimal values, field elements). `JSON.parse_string` turns every number into a `float`, so a single value from JSON is converted with `ScfgPy.json_int`, and a whole document (persisted state, which the Engine normalises itself, the vectors, driver commands) is read as Python's `json.load` would read it with `ScfgPy.from_json`. A request never carries a float where Python sends an int. Don't write float literals of 2^53 or more, because the GDScript parser misreads them. `ScfgDec` reproduces CPython's `str(Decimal)` forms (`"4.990000"`, `"1E+1"`).

## Web exports

On a web export (`OS.has_feature("web")`) there is no localhost server. `Scfg` injects the shared checkout page (`addons/scfg/web/`) into the game's own HTML page through `JavaScriptBridge` and shows the browser checkout as an overlay (`ScfgWebPage`, `ScfgOverlayCheckout`). "Browser wallet" is offered only when the page has a wallet extension for the chosen network. Copy, Paste and "View on explorer" go through the page too. Nothing touches `JavaScriptBridge` off the web.

What the export needs:

- **Export filter.** The page's files are not Godot resources, so add `addons/scfg/web/*` to the web preset's "Filters to export non-resource files/folders" (and the logo, if it is not imported as a texture). Without them the checkout page cannot be loaded, and a debug build warns, naming each missing file. `godot/demo/export_presets.cfg` is a working example: a single-threaded "Web" preset (`variant/thread_support=false`), which needs no cross-origin isolation (COOP/COEP) headers.
- **Secure context.** Wallet extensions, the clipboard and `fetch` to the RPC endpoints expect the game to be served over HTTPS (or from `localhost`). A browser refuses a Paste or Copy outside one; the sheet then shows "paste_blocked" / "Couldn't copy".
- **Persistent receipts.** `user://scfg/state.json` (receipts and pending payments) lives in `user://`, which a web export keeps in the browser's IndexedDB. IndexedDB belongs to the page's origin (scheme, host and port), not to its path. Every Godot web export uses the same database there, `/userfs`, and `user://` is a folder in it named by Godot's usual rule: `/userfs/godot/app_userdata/<application/config/name>` (the demo's is `/userfs/godot/app_userdata/SCFG Demo`). Each time a game saves, it writes the whole database back from its own in-memory copy, which it loaded at startup. So on one origin, for example a host that serves many games from the same domain:
  - two games with the same project name share `user://scfg/state.json`, so each one sees, and can overwrite, the other's receipts;
  - games with different names keep separate files, but a game deletes from IndexedDB whatever another game (another tab) saved after it loaded. This was checked with the demo in Chromium. One game open in two tabs should behave the same (the last tab to save wins): that is inferred from the same mechanism, not tested.

  The addon therefore keeps a second copy of the receipts (not the pending sessions) in the page's `localStorage` (`ScfgWebMirror`), which is written key by key, so another game never touches it. Every web save merges this tab's receipts into it (it reads the copy first, so a receipt that another tab of the same game saved stays there), and the first read of the state merges it back: a receipt the copy holds and `state.json` lacks is added (receipts only accumulate; when both hold one, `state.json`'s version is kept), and the result is saved to `user://` at once. Merged receipts are stored receipts like any other: normalised as JSON, then re-verified on the chain when the Engine starts. A state file that cannot be read leaves the copy alone too. A pending session lost with `state.json` is not in the copy; the player brings that payment back with Restore and its transaction hash. One game open in two tabs: `state.json` itself is still last-writer-wins across the tabs, but the copy only grows, except for receipts a tab removed itself (re-verification, `clear_local_data()`), so the next start merges the other tab's receipts back. `tools/run_godot_web_e2e.py` (step 4) deletes `state.json` from IndexedDB between two loads of the demo in Chromium and checks that every receipt comes back. `clear_local_data()` empties the copy as well, until another open tab of the same game saves: that tab's save merges its own receipts back into it. If localStorage is missing, blocked or full, saving to `user://` goes on and a debug build warns once ("localStorage cannot be read" / "did not keep the receipts' copy").

  The key is `scfg:<application/config/name>:<sha256 hex of the storage id>`. The storage id is the project setting `scfg/web/storage_id` when it is set to a non-empty string, else `application/config/name`. Set it when another game on your origin may have the same project name (such as `"com.example.mygame"`; with the plugin enabled it is under Project Settings > Scfg > Web > Storage Id, or add it to `project.godot` under `[scfg]` as `web/storage_id="..."`), and never change it, or the project name, after a release: the copy would be looked for under a new key. The demo's key is `scfg:SCFG Demo:25cc291f...` (sha256 of "SCFG Demo"). Two games with the same project name still share `state.json` itself, so give the game a unique `application/config/name` as well, and serve it from an origin of its own where you can. Godot reports `OS.is_userfs_persistent()` as false when it could not open IndexedDB, so everything written to `user://` is lost when the tab closes. That happens when the browser has no IndexedDB or blocks it for the page: some private-browsing modes, "block site data" settings, and pages in a restricted cross-origin iframe. In a debug build the autoload then warns once ("user:// is not persistent in this browser", via the same developer-warning path as the other setup advice), because players' receipts would not survive a reload. Release builds stay quiet; the player can still restore with a transaction hash.
- **Threads.** The addon needs no threads; RPC goes through `HTTPRequest`, which uses `fetch` on the web.

There is no counterpart of Ren'Py's `config.save_directory`: the database is always `/userfs`, and only the folder inside it follows the project name.

## M4 contracts (glue must honour)

The core leaves these to the Godot glue (autoload, sheet, page server, web bridge). Each one is a rule the M4 code must follow, not something the core checks.

- **A transport host that goes away ends its requests with `HostGone`.** When `ScfgHttpTransport`'s host Node is not in the tree, or leaves it or is freed mid-request, `post_json` returns an `ScfgErr` of kind `HostGone` (Godot only). The waiting coroutine resumes deferred, after the removal has finished, so it never calls `add_child` on a host that is busy leaving the tree. `HostGone` is not a `TransportError`, so the RPC client cools no endpoint down; the Engine contains it like any failed step. Still, keep the host (the autoload) for the whole session, and `stop()` the Worker before freeing it. At a real quit the tree is torn down with no further frame, so that deferred resume never comes: call `close()` on the transport when its host leaves for good (the autoload does in `_exit_tree`), which ends every request in flight with `HostGone` at once and refuses later ones. Otherwise the suspended coroutines are reported as "ObjectDB instances leaked at exit".
- **The page's callbacks do not keep the controller alive.** `on_tx`, `get_status` and `build_tx`, which `ScfgCheckoutController` hands to the page through `server_factory`, are bound to the RefCounted controller. They do not hold a reference to it. Call `close()` (or `cancel()` / `finish()`) before releasing a checkout controller, and `stop()` its page; the page checks `is_valid()` before calling any of them.
- **`server_factory`'s page `start()` must not suspend.** The controller calls it without `await`, and so are `stop()`, `reopen()` and `pump()`.
- **Every injected Callable is synchronous except the `fn` given to `submit`.** That covers the Engine's `rpc_factory`, `on_error` and `clock`, and the checkout controller's `server_factory`, `unready` and `browser_wallet`. `submit` itself returns its ScfgJob at once, while `fn(engine)` may be a coroutine because the Worker awaits it. The core calls every other Callable without `await`, so one that awaits hands it a function state instead of its value.
- **Build the Worker from `ScfgEngine.create()`.** `ScfgEngine.new()` keeps a bad config's TypeError in `init_error`, and every method, `snapshot()` included, then returns it. So `worker.snapshot` would be an ScfgErr. Use `create()` and handle its error, or check `worker.snapshot is ScfgErr`.
- **`restore_apply` choices are keyed by int candidate index.** A screen or bridge that holds string keys (JSON, an HTML form) converts them first: `ScfgRestore` finds no choice under a `"0"` key and silently skips that candidate.
- **Sum stored or player-supplied amounts with `ScfgDec.add_checked`.** The plain `add`/`sub`/`mul` skip Python's decimal.Overflow check and are only for operands known to be small.
- **Await a direct `.call()` on a lambda that awaits.** The coroutine lint only follows named functions, so `await f.call(...)` on an awaiting lambda is not checked.
- **State loaded from JSON is normalised by the Engine.** Godot's JSON reader turns every number in `user://scfg/state.json` into a float. `ScfgEngine` passes its `pending` and `receipts` options through `ScfgPy.from_json`, which turns each integral float below 2^53 back into an int (`units`, `log_index`, `block`, `match.value`...), so pass the parsed state straight in. Other JSON the glue feeds the core (bridge messages, page posts) needs `ScfgPy.from_json` too.

## Integration driver

`tests/integration/engine_driver.gd` uses the protocol of the TypeScript driver (`rpgmaker/test/integration/engine_driver.ts`). It reads one JSON command per stdin line and writes one `{"ok": …}` or `{"error": {"type", "code", "message"}}` reply per command. The ops are `init` (with a registry override that patches `ScfgChains.MAINNET`/`TESTNET`), the Engine actions, `snapshot`, `set_receipt` and `clear_receipts`. Results are encoded like the Tier 2 `returns` (`tests/tier2.gd`).

Godot prints its banner on stdout, so each reply line starts with `SCFG-REPLY `. `tests/integration/gd_driver.py` (`GdEngine`) ignores every other line. It skips when `SCFG_GODOT` is unset or not executable, and fails instead with `SCFG_REQUIRE_GD=1` (set in CI). `tests/integration/test_gd_core.py` holds the GDScript twins of the 14 tests in `test_js_core.py`.

stdin is read with `OS.read_string_from_stdin`. Between commands it blocks the main loop, when nothing is in flight; while a command awaits HTTP, the loop runs. Godot 4.3 returns a line in pieces of up to 1023 bytes with the newline kept. 4.4 and later strip the newline and take a buffer size, so the driver passes 1 MiB there, and `GdEngine` refuses longer commands. Commands are sent as ASCII JSON because 4.3 reads stdin as Latin-1.

`tests/integration/server_driver.gd` runs one `ScfgCheckoutServer` with fake callbacks for the shared server security suite (`tests/server_security/`), which runs every test against the Python server and the GDScript one: `SCFG_GODOT=$GODOT uv run pytest tests/server_security` (the Godot half skips without `SCFG_GODOT`, and fails instead with `SCFG_REQUIRE_GD=1`, as in CI). It reads stdin on a Thread, since the server must be pumped every frame between commands.
